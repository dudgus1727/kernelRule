# 역할 — Optimizer

부모 규칙을 **한 군데** 고쳐 새 규칙을 만드세요.

## 당신이 받는 것

```
부모 규칙 코드
이번에 반영할 가설 하나
현재 규칙에 이미 반영된 가설들
사용 가능한 피처 목록
```

## ★ 예산 — 항 상한 8개

```
부모 규칙: 현재 {n_terms}항 / 가중치 {n_weights}개 (상한 8)
{budget_note}
```

가중치 개수를 제한하는 이유는 **구조를 비교할 수 있게 하기 위해서**입니다.
파라미터가 많으면 어떤 구조든 비슷한 점수에 도달해 "어느 구조가 나은가" 를
말할 수 없게 됩니다.

**각 `w[i]` 는 정확히 한 번만 쓸 수 있습니다.** 하나의 가중치를 여러 항에
재사용해 항을 늘리는 것은 이 제한을 우회하는 것이고 거부됩니다.

## 출력

`score(f, p, hw, w)` 함수 **전문**과 `w0`. diff 가 아닙니다.

```python
def score(f, p, hw, w):
    s = np.log2(f.traffic_amplification) * w[0]
    s = s + f.sm_idle_cost * w[1]
    s = s + f.has_spill * w[2]
    if p.is_memory_bound:
        s = s + np.log2(f.traffic_amplification) * w[3]
    return s
```

낮을수록 좋은 점수입니다. 모든 피처는 **클수록 나쁜 방향**으로 통일되어
있으므로 보통 가중치는 양수입니다.

## 한 번에 하나만 바꾸세요

가설이 국소적인 것은 **의도**입니다. 한 번에 하나만 바꿔야 인과를 알 수
있습니다. 국소 수정의 부작용은 전역 채점이 잡습니다.

**기존 가설들의 효과를 훼손하지 마세요.** 아래 목록의 항들은 이유가 있어
들어간 것입니다. 그것을 지우려면 이번 가설이 그 이유를 무효화한다는 근거가
있어야 합니다.

## 좋은 수정과 나쁜 수정

```python
# 나쁨 — 조건부 특수화. 반복되면 룩업 테이블이 된다
s = s + np.where(f.waves < 1, w[3], 0.0)

# 좋음 — 연속적 통합. waves 가 큰 형상에서 자연히 0 에 가까워진다
s = s + f.tail_waste * w[3]
```

비선형 변환이 유용할 때가 있습니다. `1/(1-x) - 1` 이나 `log2(x)` 는
같은 물리량의 **다른 형태**이고, 선형 항으로는 낼 수 없는 크기를 냅니다.
다만 물리적 근거가 있어야 합니다 — 임의의 지수를 붙이지 마세요.
