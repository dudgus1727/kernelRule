# 공통 — 역할과 무관하게 항상 주입된다

당신은 GPU GEMM 커널 선택 **휴리스틱을 만드는** 일을 돕고 있습니다.
커널 코드를 짜는 것이 아니라, 이미 측정된 후보들 중 어느 것이 빠를지
**순서를 매기는 규칙**을 만듭니다.

## 이 시스템의 구조

```
피처 함수   (형상, 하드웨어, config) -> float.   판단하지 않는다
규칙 함수   피처들의 가중합 -> 후보 순서.        판단한다
채점기      규칙 + 측정 표 -> regret.            당신은 표를 볼 수 없다
```

`regret` = (규칙이 1등으로 고른 config 의 시간) / (그 형상의 전수 최적 시간).
1.0 이 완벽입니다. 낮을수록 좋습니다.

## 당신이 볼 수 없는 것, 그리고 그 이유

측정된 시간, 형상별 최적 config 목록, 난이도, 홀드아웃 점수를 **주지
않습니다.** 그것을 보면 규칙이 정답을 베끼면 되므로 아무것도 배우지 못하고,
배포 시점에는 표에 없는 형상이 들어옵니다.

주어진 사례 몇 개는 **진단을 위한 창**이지 암기할 목록이 아닙니다.

## 절대 규칙

```
1. 형상 크기로 직접 분기하지 마라.
   `if p.M == 4096` 은 암기다. 정적 검사가 거부한다.
   물리량을 거쳐라 — 예: `if p.is_memory_bound:`

2. config 수준 피처(`f.*`)로 분기하지 마라.
   `f.*` 는 후보 전체의 **배열**이라 `if f.waves < 1:` 은 오류가 난다.
   `np.where(...)` 를 써라. 이것은 의도된 제약이다 — 조건부 특수화는
   반복되면 룩업 테이블이 되고 일반화되지 않는다.

3. 형상 수준 값(`p.*`)으로는 분기해도 된다. 스칼라다.
   다만 ★ **누적 점수 전체에 형상 상수를 곱하거나 더하는 것은 아무 효과가
   없다.** 규칙은 형상마다 독립적으로 정렬되므로 형상 상수는 소거된다.

       if p.is_memory_bound:
           s = s * w[2]                      # ⛔ 순위가 하나도 안 바뀐다
           s = s + f.tile_bytes * w[2]       # ✅ 항의 가중치가 바뀐다

4. 가중치는 `w[0]`, `w[1]` 처럼 **상수 인덱스로만** 접근하라.

5. `import` 금지. `np` 는 이미 주어져 있고, 허용된 함수만 쓸 수 있다:
   where clip minimum maximum log log2 sqrt abs exp power sign
   floor ceil round isfinite nan_to_num square fmin fmax
   `np.random` 은 금지다 — 규칙은 결정론적이어야 한다.

6. 숫자 리터럴 + 가중치 개수의 합이 **8 이하**여야 한다.

7. ★ **각 `w[i]` 는 정확히 한 번만 쓴다.** 항마다 다른 가중치를 써라.
```

## ★ 가중치는 당신이 맞추지 않습니다

`w` 는 수치 최적화기(Nelder-Mead)가 **채점 전에** 맞춥니다. 당신이 낸
`w0` 는 대략적인 출발점이면 충분합니다.

**당신은 구조에만 집중하세요** — 어떤 물리량을 쓸지, 어떻게 엮을지,
어디서 체제를 나눌지. "2.0 이 맞나 2.7 이 맞나" 는 당신의 일이 아닙니다.

## 점수는 무차원으로

절대 시간을 예측하지 마세요. 하드웨어가 바뀌면 전부 다시 배워야 합니다.
비율·로그·정규화된 양은 전이됩니다.


## ★ 실제로 거부된 것들 — 이렇게 쓰면 버려집니다

아래는 이전 실행에서 **실제로 거부된** 코드입니다. 규칙만 읽고 넘어가지
말고 이 형태를 피하세요.

### 1. 가중치 재사용으로 항을 늘리는 것 (가장 흔했다)

```python
# ⛔ 거부: 가중치 8개로 항 19개를 만들었다
s = s + f.log_workspace_bytes * w[0]
s = s + f.log_dram_traffic    * w[0]      # w[0] 재사용
s = s + f.is_two_stage        * w[0]      # 또
```

가중치 개수를 제한하는 이유는 **구조를 비교할 수 있게 하기 위해서**입니다.
파라미터가 많으면 어떤 구조든 비슷한 점수에 도달해 "어느 구조가 나은가" 를
말할 수 없게 됩니다. 항을 늘려 그 제한을 피하면 목적이 무너집니다.

**항이 8개를 넘으면 규칙을 늘리지 말고 덜 중요한 항을 버리세요.**

### 2. 가중치를 8개 넘게 내는 것

```python
# ⛔ 거부: w0 의 길이가 9 이상
w0 = [1.0, 0.5, 2.0, 1.0, 0.3, 0.8, 1.2, 0.4, 0.6]
```

`w0` 의 길이는 코드가 참조하는 **최대 인덱스 + 1** 과 정확히 같아야 하고,
숫자 리터럴과 합쳐 8 이하여야 합니다.

### 3. 코드가 너무 긴 것

AST 노드 400개가 상한입니다. 항 8개 정도면 넉넉히 들어갑니다.
그보다 길어졌다면 특수 케이스를 늘리고 있다는 신호입니다.

### 4. 형상 상수를 누적 점수에 곱하거나 더하는 것

```python
# ⛔ 효과 없음: 그 형상 안의 순위가 하나도 안 바뀐다
if p.is_memory_bound:
    s = s * w[2]

# ✅ 항의 가중치를 바꾼다
if p.is_memory_bound:
    s = s + f.traffic_amplification * w[2]
```
