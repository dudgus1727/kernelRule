## ★ 알고 나서 다시 한다면

**"사람 몇 주를 하룻밤으로" 라는 주장에는 이 숫자가 필요하다** — 시행착오
비용이 아니라 **결과에 도달하는 최소 비용**이다.

지금까지 살아남은 결과(`conclusion.md`)를 얻는 데 필요한 실행만 세면:

| 필요한 것 | 실행 | 호출 | 왜 필요한가 |
|---|---:|---:|---|
| 기준선 6시드 | 6 | ~930 | **시드 폭 0.0977 을 알아야** 나머지를 해석한다 |
| 피처 설명 A/B 각 6시드 | 12 | ~1,860 | 유일하게 폭을 넘은 결과 (0.058) |
| F1 FeatureWriter | — | 20 | 재발견 7~9/24. 관찰이라 반복 불필요 |
| Architect A/B | — | 20 | 각 10회 |
| **합계** | **18** | **~2,830** | 실제 5,019 의 **56%** |

**44% 가 시행착오였다.** 큰 항목:

```
78분 1,400호출을 통째로 잃음        dump() 를 안 불렀다 (D-33)
seedabl 4묶음 x 3시드 = 12실행       3시드로는 못 가른다는 걸 몰랐다 (D-40)
newaxes A/B 6실행                   같은 이유
selB 5실행                          시드 선택이 편향인지 확인 (D-46)
featwriter 3회 시도                 검사기 버그 둘 (D-37, D-38)
```

**⚠️ 이 추정에는 후견지명이 들어 있다.** "6시드가 필요하다" 는 것도
시드 폭을 재고 나서 안 것이다. **처음부터 6시드로 시작할 근거는 없었다** —
F-10 이 "3개 이상" 이었고 그것이 당시의 최선이었다. 정직하게 쓰면
**"결과를 알고 재현만 한다면 56%"** 이지 **"잘 했으면 56%였다" 가
아니다.**

그리고 **`luna` 로 다시 하면 더 비싸다** — 출력 2.7배.
