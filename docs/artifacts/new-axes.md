# 2번 — 새 축은 쓰이지만 도움이 되지 않는다

**측정일** 2026-08-22 · `gpt-5.4` · 6실행 × 12라운드 × 12규칙 = 930 호출
**재현** `python3 experiments/new_axes.py 12 3` → `score_new_axes.py`

```
조건 A   사람이 쓴 24개
조건 B   24 + F1 이 만든 새 축 10개 = 34개
같은 시드 3개 / 12라운드 / 씨앗 없음 / 피처 설명 있음
```

새 축 10개는 **손으로 적지 않고 계산했다** — 생성 16개 중 기존과 스피어만
> 0.95 인 6개를 중복으로 뺀 것이다 (§8.4).

---

## 결과

| 조건 | 표본내 중앙 | 최악 | 구조 HO 중앙 | 최악 | 홀드아웃 승패 |
|---|---:|---:|---:|---:|---|
| A (24개) | 1.0819 | 1.0997 | **1.0877** | 1.1496 | 11승 8패 1무 |
| B (34개) | **1.0735** | 1.0933 | 1.1034 | 1.1429 | 9승 9패 2무 |
| 벤더 ★관문 | — | — | **1.0737** | — | — |

```
표본내      B 가 0.008 낫다
구조 홀드아웃  A 가 0.016 낫다      ★ 방향이 뒤집힌다
```

**표본내에서 좋아지고 홀드아웃에서 나빠지는 것은 과적합의 형태다.**
피처가 늘면 학습 형상에 맞출 방법이 늘어난다.

### ★ 다만 이 차이는 시드 흔들림보다 작다

조건 A 는 앞선 실험의 "씨앗 없음(설명)" 과 **같은 조건**이다 (프롬프트·
레지스트리·분할이 같고 LLM 시드만 다르다). 두 실행을 합치면 같은 조건의
시드 6개가 된다:

```
구조 홀드아웃   1.0518  1.0714  1.0757  1.0877  1.1093  1.1496
                └──────────── 폭 0.098 ────────────┘
```

**A/B 차이 0.016 은 이 폭의 6분의 1이다.** 시드 3개로는 가를 수 없다.
정직한 판정은 **"구분 불가"** 다.

## ★ 쓰이기는 쓰인다

| 새 축 | 아카이브 35규칙 중 |
|---|---:|
| `split_k_io_amplification` | **20** |
| `split_k_tail_fraction` | 5 |
| `wave_tile_imbalance` | 5 |
| `cta_k_passes_per_output` | 4 |
| `cta_l2_residency_pressure` | 3 |
| `cta_payload_per_thread` | 2 |
| `roofline_excess_ratio` | 1 |
| `split_k_granularity_loss` | 1 |
| `cta_lane_waste_ratio` | **0** |
| `thread_underutilization_ratio` | **0** |

**8/10 이 쓰였고, 최고 규칙에도 시드마다 1~2개가 들어갔다.** "34개를 줬는데
기존 24개만 쓴다" 가 아니다 — LLM 은 새 축을 골랐다.

`split_k_io_amplification` 이 20/35 로 지배적이다. 처음에는 "기존
`split_k_cost` / `log_workspace_bytes` 의 더 나은 형태일 뿐" 으로 의심했는데
**틀렸다** — 상관이 낮다:

```
vs split_k_cost         sp 0.464  pe 0.432
vs log_workspace_bytes  sp 0.298  pe 0.414
```

**새 축이 맞다.** 20/35 로 선택된 것이 우연이 아니다.

## 판정 — F1 은 "가능성 증명" 에 머문다

```
만들 수 있다      ✅  원시 값만으로 24개 중 7~9개 재발견 + 새 축 10개
쓰인다           ✅  8/10 이 아카이브에, 1~2개가 최고 규칙에
새 정보를 담는다   ✅  split_k_io_amplification 상관 0.30~0.46
regret 을 개선한다 ❓  ★ **측정 불가** — 차이 0.016 이 시드 폭 0.098 안이다
```

**"도움이 안 된다" 가 아니라 "못 쟀다" 가 정확하다.** 다만 두 가지가
열려 있다.

**1. 여지가 없었을 수 있다.** 조건 A 가 이미 벤더(1.0737)와 대등하다.

> ⚠️ **"대등" 이 상쇄의 결과였다** (2026-08-22 확인). 체제별로 부호가
> 뒤집힌다:
> ```
> 빠른 12형상   규칙 1.0806  vs  벤더 1.0994    ★ 이긴다. 6실행 중 5개
> 느린  8형상   규칙 1.0909  vs  벤더 1.0363       진다
> ```
> 전체 geomean 만 보면 "대등" 인데 **빠른 체제에서 이기고 느린 체제에서
> 지는 것이 상쇄**된 것이다. §9.2b("여지 없는 체제에서는 규칙 기반이 고정
> config 를 못 이긴다")와 일관된다. 서술이 완전히 다르므로 §30.4 의 층화
> 보고가 여기서도 필수다.
>
> 그리고 **여지가 큰 체제로 옮겨도 폭 문제는 그대로다** — 시드 폭이
> 빠른 체제 0.1119 / 느린 체제 0.0763 으로 **빠른 쪽이 더 크다**
> (`experiments/seed_spread.py`).

**2. 피처가 늘면 탐색이 흩어진다.** 34개는 12라운드로 탐색하기에 많을 수
있다. 앞서 피처 설명을 준 뒤 **쓰인 피처 종류가 13~17 → 12~13 으로 줄면서**
결과가 좋아진 적이 있다 (`artifacts/feature-descriptions.md`).
**선택지를 늘리는 것과 좁히는 것 중 후자가 이겼다.**

→ 새 축을 **전부 넣는 대신 한두 개만** 넣어 보는 것이 다음 실험이다.
`split_k_io_amplification` 하나만 넣으면 34개의 탐색 비용 없이 그 축의
값어치만 잰다.

## 부수 관찰

**조건 A 의 단일 최고가 1.0518 이다** (s0, 구조 홀드아웃). 벤더 1.0737 을
0.022 앞선다. 그러나 같은 조건의 다른 시드가 1.1496 이라 **중앙값으로
보고해야 한다** (§F-10).

**한 번도 안 쓰인 축 둘** — `cta_lane_waste_ratio`,
`thread_underutilization_ratio`. 둘 다 스레드 수준 낭비를 재는데, 이미
`occupancy_deficit` 과 `tail_waste` 가 그 영역을 덮는다. 중복 판정
(스피어만 0.95)을 통과했지만 **LLM 이 쓸모없다고 판단한 셈**이다.
자동 중복 판정보다 사용 여부가 더 엄격한 필터일 수 있다.
