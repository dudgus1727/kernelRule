## 무엇을 묻는가

D-85 에서 Critic 의 "설명 불가" 지목이 **뒤쪽 항에 몰렸다**.

```
지목률     w0 0%  w1 17%  w2 17%  w3 33%  w4 0%  w5 17%  w6 50%  w7 83%
손상 순위  w0 0.90                                          w6 0.38  w7 0.81
```

`w[7]` 은 손상 순위 0.81 로 **오히려 중요한 축**인데 83% 가 지목됐다.
두 해석이 가능하다.

```
1  진화가 항을 뒤에 붙인다 -> 뒤 항이 실제로 더 뒤죽박죽이다   (신호)
2  LLM 이 마지막에 본 것을 지목하는 위치 편향                (잡음)
```

**도구가 무엇을 재는지 모르면 통과 조건을 다시 짜도 소용없다.**

## 방법 — 순서만 바꾼다

```
항 순서를 무작위로 섞고 `w` 인덱스를 새 순서로 **다시 매긴다**
★ 인덱스를 안 고치면 모델이 원래 순서를 그대로 읽는다
식 자체는 글자 하나 안 바꾼다
```

`kernelrule/rules/ablate.py::reorder_terms`. 대상 6규칙은 전부 **한 줄에
항 하나**이고 분기가 없다(확인 완료) — 형태가 다르면 `AblateError` 로
거부한다. 시드 `20260828` 고정.

## 판정 — 미리 적는다

**같은 식이 다시 지목되는가**를 본다. 원래 심사에서 지목된 식의 집합을
`A`, 섞은 뒤 지목된 식의 집합을 `B` 라 하면 규칙마다 자카드 유사도
`|A∩B| / |A∪B|` 를 잰다.

```
자카드 중앙 >= 0.6   ★ 편향이 아니다. 지목이 식을 따라간다 -> 새 통과 조건으로 간다
자카드 중앙 <= 0.2   ★ 편향이다. 프롬프트를 고쳐야 한다
                    (항 번호를 지우거나 제시 순서를 무작위화)
그 사이              부분 편향. 지목의 신뢰도를 그만큼 할인하고
                    새 통과 조건에서 "지목 강도" 대신 "지목 여부" 만 쓴다
```

**보조 지표 — 새 위치의 지목률**

```
섞은 뒤에도 마지막 두 자리(w6, w7)의 지목률이 높으면  ★ 위치 편향
원래 뒤에 있던 식들이 앞으로 가서도 지목되면          ★ 식을 따라간다
```

```
원래   w6, w7 지목률 8/12 = 67%
섞은 뒤 같은 자리(w6, w7)의 지목률이 60% 이상이면 위치 편향 쪽
```

⚠️ **표본은 규칙 6개다** (원칙 28). 항 단위 p 를 주 근거로 쓰지 않는다.

⚠️ **지목 개수 자체가 달라질 수 있다.** 그것도 관찰이다 — 같은 규칙을
다른 순서로 보여 줬을 때 판정 수가 크게 변하면 그 자체가 불안정성이다.
