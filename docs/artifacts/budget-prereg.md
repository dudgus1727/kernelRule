# 사전 등록 — 예산 8 vs 16, 순위 손실 단독

**LLM 호출 0회 시점에 쓴다.** 근거:
[feature-overlap.md](feature-overlap.md), [D-105](../decisions.md),
[D-106](../decisions.md).

## 1. 묻는 것이 바뀌었다

```
원래   "예산이 진화를 제약하나"
★ 지금  "예산이 **벽을 뚫나**"
```

벽은 D-104 다: regret 1.11~1.13 인 규칙은 상위100 tau 가 0 근처고,
tau 0.33~0.37 인 규칙은 regret 가 1.59~1.69 다. 순서를 바꿔도 안
움직였다.

## 2. 조건

```
BUDGET 8 vs 16 · 목적함수 순위 손실 단독(전환 없음) · 3시드씩
12라운드 · 라운드당 12제안 · seed-from runs/f1pipe-F3-arch24
모델 gpt-5.6-luna · 표 rtx-a6000-sm_86-c63710df · 분할 nk11008
```

**두 팔 다 새로 돌린다.** 기존 `bud08` 을 기준선으로 쓰지 않는다 —
D-106 으로 노드 상한 배선이 바뀌었고, 예산 8 에서는 값이 같지만 "같은
코드에서 나온 3시드씩" 이 더 읽기 쉽다.

★ **첫 라운드 프롬프트를 눈으로 확인하고 시작한다** — 시스템·사용자
양쪽이 같은 숫자를 말하는지. 이 자리에서 두 번 틀렸다 (D-105, D-106).

## 3. 주 지표 — 전부 홀드아웃 20형상

```
★ 예산 16 팔의 규칙을 **regret 으로 재적합**했을 때 상위100 tau
   -> 8 에서는 -0.059~0.058 이었다. 16 에서 오르나
★ 학습-홀드아웃 격차 (과적합)
   항 수 분포 — 16 을 다 채우는가
   순위 적합 tau / regret · 무작위 바닥 (원칙 7)
```

## 4. 판정선

```
regret 재적합 tau 중앙 >= 0.20  ★ 예산이 벽을 뚫었다
                    <= 0.10   벽은 예산 탓이 아니다
              0.10~0.20        구분 불가
```

동시에 regret 가 1.20 이하여야 "뚫었다" 로 읽는다 — tau 만 오르고
regret 가 1.6 대로 가면 그것은 순위 팔로 옮겨간 것뿐이다.

항 수:
```
16항을 쓰는 규칙이 3시드 중 0개   ★ 예산이 구속력이 없었다 (실험 무효)
중앙 항 수 <= 9                  예산을 줘도 안 쓴다
```

## 5. ★ 예상 (틀리면 그대로 남긴다)

**예산 16 은 벽을 못 뚫는다.** regret 재적합 tau 가 −0.06~0.06 띠 안에
남을 것으로 본다. 근거는 두 계열의 축 자카드가 **1.000** 이라는 것 —
담을 축이 모자란 것이 아니다 (feature-overlap.md §5).

