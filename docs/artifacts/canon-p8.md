# ★ 대표값 재측정 — **프롬프트 정리는 성능에 안 닿았다. 라운드가 닿았다**

> **재현**: 캠페인 `python3 experiments/f1_pipeline.py F3 --stage 3
> --seed-from runs/F3rw-p8-old --rounds 24 --n-seeds 6 --workers 6
> --parameters 8 --tag F3rw-p8` (LLM **500회**)
> 채점 `python3 experiments/sigma_5090.py --bundle datasets/rtx-a6000-sm_86-c63710df
> --env-hash c63710df --runs F3rw-p8-s0 ... --out docs/artifacts/canon-p8.json`
> **실험 계획서**: [canon-rerun-prereg.md](canon-rerun-prereg.md)
> **원자료**: `canon-p8.json` · `early-stop-cost.json` · `patience-canon.json`

## 1. 결과 — 판정선 안이다

```
옛 대표값  1.0762   (옛 프롬프트 · 라운드 12 · patience 10 · 6시드)
★ 새 대표값 1.0944  (새 프롬프트 · 라운드 24 · patience 3  · 6시드)
                   범위 1.0821~1.1138   σ = 0.0113  95% CI [0.0071, 0.0277]

차이 +0.0182   <   판정선 0.0305 (σ 95% 상한)   ★ 구분 불가
```

실험 계획서대로 **새 값을 대표값으로 삼는다** — 조건 통일이 우선이다.

## 2. ★ 그런데 그 +0.0182 가 어디서 왔는지 잴 수 있었다

실험 계획서는 "두 변수(프롬프트·라운드)의 효과를 분리하지 않는다" 였다.
캠페인 안에서는 그렇다. **그러나 옛 실행의 아카이브를 잘라 보면 LLM
0회로 달라진다.**

옛 대표값 6실행의 아카이브를 **r<=5 까지**로 자르고 (새 캠페인이 실제로
멈춘 지점) 최종 채점했다:

| | 중앙 | 새 캠페인과의 차 |
|---|---:|---:|
| 옛 실행, 전체 12라운드 | 1.0762 | — |
| **옛 실행, r<=5 까지** | **1.0949** | **+0.0005** |
| **새 캠페인 (r5~r7 에서 종료)** | **1.0944** | — |

```
★ 조기 종료의 값        +0.0187   (1.0949 - 1.0762)
★ 프롬프트 정리의 값     -0.0005   (1.0944 - 1.0949)  = 없다
```

**같은 라운드 예산에서 옛 실행과 새 실행이 같은 값을 낸다.** hw 자동
생성(D-113·116·117) · 가설 필드 허용 목록(D-117) · 파라미터 표기(D-128)
— **어느 것도 성능에 안 닿았다.**

## 3. ⚠️ 그러면 `patience=3` 이 문제다 — D-129 의 기준이 틀린 통화를 썼다

D-129 는 "놓칠 개선" 을 **`best_val_regret`** (루프가 라운드마다 적는
값)으로 쟀다. 그런데 **우리가 보고하는 것은 최종 채점**(체제별 재적합
-> 홀드아웃)이고, 둘은 같은 것이 아니다.

```
D-129 의 추정 (best_val_regret 기준)   놓칠 개선 중앙 0.0000 · 최대 0.0060
★ 실측 (최종 채점 기준)                 +0.0187
```

**세 배 차이다.** 원칙 37/40 의 자리다 — 재는 지표가 판정에 쓰는 지표와
같아야 한다. 최종 채점은 체제별로 다시 맞추므로 **뒤 라운드의 구조에서
더 뽑아낸다**. 루프의 val 은 그것을 못 본다.

### 같은 기준을 **최종 채점 통화로** 다시 적용하면

옛 실행의 아카이브를 patience 별 가정 종료 라운드에서 잘라 채점했다:

| patience | 가정 종료 (6시드) | 최종 채점 중앙 | ★ 놓칠 개선 중앙 | 최대 |
|---:|---|---:|---:|---:|
| 3 | r6 r11 r3 — r10 r11 | 1.0788 | +0.0015 | +0.0051 |
| **5** | r7 — — — — — | **1.0762** | **+0.0000** | +0.0046 |
| 7 | — | 1.0762 | +0.0000 | +0.0000 |
| 10 | — | 1.0762 | +0.0000 | +0.0000 |

**가정 종료 지점에서는 patience=3 도 +0.0015 뿐이다.** 그런데 새
캠페인은 **훨씬 일찍 멈췄다**:

```
옛 실행의 가정 종료 (patience 3)   r6 · r11 · r3 · — · r10 · r11   중앙 ~r8
★ 새 캠페인의 실제 종료             r4 · r5 · r5 · r6 · r6 · r6    중앙 r5.5
```

새 실행들은 `best_val_regret` 이 **처음부터 평평했다** (s0 은 7라운드
내내 1.1177 로 한 번도 안 움직였다). 그래서 "새 셀이 3라운드 없으면"
조건이 먼저 걸렸다. **캠페인마다 정체 시점이 다르고, patience=3 은 그
변동에 민감하다.**

## 4. 라운드가 산출물이 됐다

```
종료 라운드   5 · 6 · 6 · 7 · 7 · 7      중앙 6.5   평균 6.3
LLM 호출      ★ 500회 (6실행)   — 12라운드 고정이면 약 2,800회였다
```

**"12라운드 돌렸다" 가 "수렴까지 평균 6.3라운드" 가 됐다.** 다만 위
§3 대로 그 수렴은 **최종 채점 통화로는 아직 0.019 남아 있다.**

```

```
