## 무엇을 묻는가

**"진단 리포트와 가설이 기여하는가."**

§16.1 이 이 저장소의 핵심 주장 중 하나인데 **한 번도 안 쟀다.**
Analyst 는 전체 호출의 약 8% 를 쓴다.

```
조건 A   Optimizer 만. ★ 진단 리포트를 **만들지도 않는다**
         (만들어 놓고 안 주면 "있는데 안 쓴다" 가 되어 다른 조건이 된다)
조건 B   + Analyst  <- 지금까지의 모든 실행이 이 조건이다
```

### ★ 조건 A 의 Optimizer 프롬프트 — 무엇을 지웠나

처음 계획은 `hypothesis` 자리에 "(가설 없음…)" 을 넣는 것이었다.
**그것은 다른 조건이 된다** — 모델이 "가설이 있는데 비어 있다" 로
읽는다. 진단 리포트를 만들지도 않는 것과 같은 원칙으로, **자리 자체를
없앤다.**

조건 A 의 프롬프트는 조건 B 의 프롬프트에서 **아래를 지운 것**이다.
새 문장은 하나도 안 넣었다.

```
1  "당신이 받는 것" 목록의 두 줄
     이번에 반영할 가설 하나 / 현재 규칙에 이미 반영된 가설들
2  "가설이 국소적인 것은 **의도**입니다. " (한 문장 앞부분)
3  "**기존 가설들의 효과를 훼손하지 마세요.** …" 문단 전체
4  "## 현재 규칙에 반영된 가설" 절과 "## 이번 가설" 절 (제목 포함)
```

**검증** 조건 A 의 프롬프트가 조건 B 의 **문자 단위 부분수열**이다 —
삭제만 일어났다는 뜻이고 `test_optimize_prompt_without_analyst_is_a_deletion`
이 고정한다. 렌더링된 전문에서 "가설" 이 **0회** 나온다 (B 는 7회).

⚠️ **그래도 Optimizer 프롬프트가 두 조건에서 다르다.** Optimizer 는
가설을 중심으로 쓰인 역할이라 Analyst 를 빼면 프롬프트가 안 바뀔 수
없다. 그것을 숨기지 않고 위에 적는다.

## 표본 단위와 지표

```
표본 하나 = 실행 하나 (원칙 28)
주 지표   구조 홀드아웃 regret (정준 절차: 체제별 적합 -> 체제별 평가 -> 결합)
검정      Mann-Whitney U (양측). ★ 3 vs 3
```

## ★ 검정력 — 3 대 3 은 약하다. 미리 적는다

```
3 vs 3 의 최소 가능 p (완전 분리, 양측) = 0.10
★ 즉 **어떤 결과가 나와도 p < 0.05 가 될 수 없다.**
```

**그러므로 유의성으로 판정하지 않는다.** 대신:

```
범위가 겹치지 않는다        ★ 기여한다는 쪽의 증거 (3 vs 3 에서 낼 수 있는 최대)
겹친다                     구분 불가
차이 중앙값이 시드 폭 이내   ★ 0.0124 (D-53). 이 안이면 어차피 못 가린다
```

**"차이가 시드 폭보다 큰가" 가 실질 기준이다.**

## 함께 볼 것 — 성능이 아닌 관찰

성능 차이가 시드 폭에 묻힐 가능성이 크다. 그래서 **과정**을 함께 센다.

```
1  라운드별 개선 곡선 — A 가 더 일찍 정체하는가
2  아카이브 셀 수 — 다양성이 다른가
3  ★ 항의 종류 — A 의 규칙이 쓰는 피처 수 (D-83 의 축)
4  거부율 — 가설 없이 만든 규칙이 더 자주 거부되는가
5  채택률 — 라운드당 아카이브 갱신 수
6  ★ 비용 — A 가 실제로 몇 % 싼가 (예상 8%)
```

**3번이 특히 중요하다** — D-83 에서 "규칙이 쓰는 피처 수" 가 요구율과
붙어 있었다. Analyst 가 없으면 그 축이 어떻게 되는지 본다.

## 판정 — 미리 적는다

```
B 가 낫고 범위가 안 겹친다
  ★ 진단 리포트가 기여한다. §16.1 의 직접 증거
겹치지만 차이가 시드 폭보다 크다
  ★ 방향은 있으나 3실행으로는 못 굳힌다. 6실행으로 갈지 판단
차이가 시드 폭 이내
  ★ 호출의 8% 를 다른 데 쓸 수 있다는 신호. 다만 "기여 없음" 은 아니다
A 가 낫다
  ★ 예상 밖. 가설이 방향을 좁혀 탐색을 해칠 수 있다 — 그것도 결과다
```

**어느 경우에도 실행을 버리지 않는다.**

## 부분 완주 처리 — 미리 정한다

```
A 3 / B 2 처럼 불균형하게 끝나면
  ★ 불균형을 **보고하고** 있는 것만으로 비교한다
  ★ 시드를 골라 버리지 않는다 (D-50)
  검정력이 더 낮아진 것을 명시한다 (2 vs 3 은 3 vs 3 보다 약하다)
```

## 표본을 나중에 늘릴 수 있다

씨앗을 `--seed-from` 으로 고정했으므로 **전이가 끝난 뒤 시드 3개씩 더
돌려 6 대 6 으로 합칠 수 있다.**

⚠️ **단 그 사이에 루프 코드가 안 바뀌어야 한다.** 5090 전이 작업이
`kernelrule/core/loop.py` 나 Optimizer 프롬프트를 건드리면 합칠 수
없다 — 그때는 그 사실을 기록하고 새 계열로 다룬다.
