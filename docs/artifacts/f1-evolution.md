## 설계 — 두 팔 대칭

```
F1 팔     F1 21개 라이브러리 + architect-try09 씨앗 (8항, p.* 분기 있음)
사람 팔    사람 24개 + architect-try05 씨앗 (8항, np.where 분기 3개)

같은 시드 수 6, 같은 라운드 12, 같은 제안 12, 같은 모델
두 씨앗 모두 **같은 프롬프트**에서 나왔다 (_rules_edit 모순 제거 후)
```

**시드 6개로 정한 이유:** 시드 폭이 주 지표 중 하나다 (§3 확인). 3개로는
폭을 못 잰다.

## 목적과 예상

```
목적   "F1 라이브러리로 규칙을 세울 수 있는가"
       ★ 두 팔의 차이를 재는 것이지 벤더를 이기는 것이 아니다

예상   사람 팔이 낫다 — 2단계에서 학습 regret 이 이미 0.05~0.12 차이났다
       ★ F1 팔이 따라잡으면 그것이 발견이다
       못 따라잡아도 실패가 아니다 — "라이브러리가 결과를 정한다" 가 결과
```

## 주 지표

```
구조 홀드아웃 중앙 + 사분위        두 팔 각각
★ 시드 폭 (표준편차)               §3 의 확인 — F1 이 더 넓은가
```

**§3 가설:** 2단계에서 학습 regret 폭이 사람 0.079 vs F1 0.348 (4.4배)
였다. **"좋은 라이브러리는 아무렇게나 골라도 그럭저럭, 부실한 것은 잘
골라야 한다"** 면 진화의 시드 폭도 F1 이 클 것이다.

## ★ 스필 가설 — 실행 전에 약해졌다

**원래 가설:** F1 에 `has_spill` 대응(이진형)이 없어서 "켜지면 배제" 를
선형 가중합으로 표현하기 어렵고, 그것이 F1 팔의 핸디캡이다.

**실행 전에 값을 쟀다. 가설이 약해진다.**

| | 비스필 최대 | 스필 중앙 | 간격 |
|---|---:|---:|---:|
| `has_spill` (사람, 이진) | 0.00000 | 1.00000 | +1.000 |
| `spill_magnitude` (사람, 연속) | 0.00000 | 2.93547 | +2.935 |
| `spill_burden_ratio` (F1, 연속) | 0.00000 | 0.05678 | +0.057 |

**셋 다 완벽히 분리된다.** `spill_burden_ratio` 는 비스필에서 정확히 0
이므로 **사실상 문턱 역할을 한다.** 차이는 분리가 아니라 **배율**이고,
배율은 가중치 최적화기가 고친다.

```
씨앗의 스필 항 가중치
  사람 팔   w[0] = 1.0   np.where(has_spill, magnitude + has_spill, has_spill)
  F1 팔     w[5] = 1.0   spill_burden_ratio
```

**따라서 "이진형이 없어서 진다" 는 예상하지 않는다.** F1 팔이 뒤처지면
다른 데를 봐야 한다.

**남은 우려 하나:** 스필 무리 안의 변동이 다르다 —
`spill_magnitude` 는 2.94~3.14 (거의 일정), `spill_burden_ratio` 는
0~0.157 (3배 변동). 적합기가 `w[5]` 를 키워 스필을 지배적으로 만들면
그 3배 변동도 함께 증폭된다. **그것이 노이즈면 손해다.**
결과를 보고 `w[5]` 가 얼마나 커졌는지 확인한다.

## 결과 (2026-08-27)

12실행(두 팔 6시드 x 12라운드) 완료. 채점은 최종 채점 절차(SOL 2분할 ->
체제별 재적합 -> 구조 홀드아웃).

### 주 지표

| | **F1 21개** | **사람 24개** |
|---|---:|---:|
| 구조 홀드아웃 중앙 | 1.1195 | **1.0762** |
| 사분위 | [1.1108, 1.1328] | [1.0706, 1.0834] |
| 범위 | 1.0954~1.1430 | 1.0566~1.0919 |
| **★ 시드 폭 (표준편차)** | **0.0177** | **0.0124** |
| 표본내 중앙 | 1.0906 | 1.0495 |
| 표본내-홀드아웃 격차 | +0.0290 | +0.0267 |
| 셀 점유 중앙 | 8 | 8 |

```
중앙 차이 (F1 - 사람)   +0.0433
Mann-Whitney            p = 0.002
시드 폭 σ               0.0274 (D-53)
```

**차이가 시드 폭을 넘고 유의하다.** 실험 계획서에 적은 예상("사람 팔이 낫다")
대로다. **F1 라이브러리로는 사람 24개를 못 따라잡는다.**

일반화 격차는 두 팔이 거의 같다 (+0.029 vs +0.027) — F1 이 더 과적합한
것이 아니라 **출발점부터 낮다.**

### ★ §3 가설 — 폭 차이는 진화가 크게 줄인다

```
2단계 (Architect 10회)   사람 0.079  F1 0.348   4.4배
3단계 (진화 6시드)        사람 0.0124 F1 0.0177  1.42배
```

**예상보다 훨씬 작다.** "부실한 라이브러리는 잘 골라야 한다" 는 방향은
맞지만(F1 이 여전히 넓다), 진화 12라운드가 그 차이를 4.4배 -> 1.4배로
좁힌다. **초기 선택의 운은 진화가 상당 부분 흡수한다.**

### ★ 관찰 1 — F1 에서 분기가 전멸했다

```
           씨앗            진화 후
F1        if 1개          if 0, where(p) 0    ★ 6/6 에서 사라짐
사람 24개   where(p) 3개    where(p) 2~4개      6/6 유지
```

F1 씨앗의 `if p.roofline_arithmetic_intensity_deficit > ...:` 가 **여섯
실행 전부에서 없어졌다.**

**그렇다고 형상 수준 값을 안 쓰는 것은 아니다.** 4/6 이 `p.*` 를
**곱셈 인자**로 쓴다.

```python
s = s + (f.register_file_footprint_fraction
         * p.roofline_compute_time_fraction) * w[1]
```

이것도 정당한 재가중이다 — 형상마다 그 항의 실효 가중치가 달라진다.
**분기(이산)가 아니라 곱셈(연속)으로 체제를 표현한다.**

⚠️ **처음에 "p.* 분기 0/6" 만 보고 "형상 수준 피처를 안 쓴다" 로 읽을
뻔했다.** `if` 와 `np.where(p...)` 만 세는 계측이었다 (원칙 14).

### ★ 관찰 2 — F1 에서 가중치가 폭주한다

```
|w| 최대
  F1        24,171 / 75,048 / 179,314 / 450,951 / 679,325 / 4,159,634
  사람 24개  8.6 / 12.7 / 16.9 / 45.1 / 197.6 / 7,663
```

**자릿수가 셋 이상 다르다.** F1 피처가 대부분 [0, 0.2] 로 정규화돼 있어
적합기가 배율을 크게 키운다. 순위만 보는 목적함수라 배율 자체는
무해하지만, **불변식 경고("초기값의 100배 초과")가 F1 팔에서 상시
발화한다** — 감시가 신호를 잃는다 (원칙 11).

**★ 고쳤다 (D-70).** 절대 배율을 버리고 **실효 기여도**로 바꿨다 —
`w[i]` 하나만 0 으로 두고 점수를 다시 계산해 형상 안 산포를 잰다.

```
|w| 최대          F1 75,048~770,164   사람 9.4~45.1    자릿수 4 차이
기여도 최대/중앙    F1 27.4~45.6배      사람 15.2~15.4배  같은 자릿수
```

스케일 불변이라 라이브러리를 바꿔도 같은 기준으로 읽힌다.

음수 가중치도 F1 이 더 많다 (2~3 vs 1~2). 피처가 전부 "클수록 나쁨"
이라고 선언돼 있으므로 음수는 **선언과 실제가 어긋난다**는 뜻이다.

### 스필 — 실험 계획서에 적은 우려가 현실이 됐다

```
spill_burden_ratio 의 가중치
  s0 2,660  s1 75,048  s2 4,901  s3 5.5  s4 25,937  s5 1,659
사람 팔 스필 항 가중치
  4.8 ~ 28.8
```

실행 전에 이렇게 적었다.

> 적합기가 `w[5]` 를 키워 스필을 지배적으로 만들면 그 3배 변동도 함께
> 증폭된다. **그것이 노이즈면 손해다.**

**실제로 키웠다.** 다만 이것이 +0.0433 의 원인인지는 이 자료로 말할 수
없다 — n=6 이고 `s3`(가중치 5.5)의 홀드아웃 1.1107 이 중앙보다 오히려
좋다. **원인 지목은 하지 않는다.**

그리고 **"이진형이 없어서 진다" 는 예상하지 않았고, 그 예상은 지킨다** —
분리는 완벽했고 문제는 배율이었다 (실행 전 기록).
