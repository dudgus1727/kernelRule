# 사전 등록 — D-75 경로 시험 2차 (2026-08-28)

> **★ LLM 호출 0회 상태에서 작성했다.**
> **명령** `python3 experiments/f1_pipeline.py F3 --max-new-features 1
> --rounds 4 --n-seeds 3 --tag d75run2`
> **모델** `gpt-5.6-luna` / medium (`DEFAULT_MODEL` 고정 — D-45, 원칙 25)
> **표** `datasets/rtx-a6000-sm_86-c63710df` (dev-cu124).
> **성능 수치를 인용하지 않는다**
> **예상 비용** 약 160호출 (3시드 x 4라운드 x 최대 15)

## 왜 다시 하는가

1차(D-79)는 가설 10건뿐이었다. 기준선 17.9% 에서 **0건이 우연일 확률이
14%** 라 아무것도 판정하지 못했다. **표본을 늘린다.**

## ★ 1차와 달라진 것 — 억제 문구를 뺐다

```
뺀 것   "한 라운드에 만들 수 있는 축은 한둘입니다.
        정말 없는 축일 때만 채우세요"
```

**근거는 결과가 아니라 설계다.** 기준선 17.9% 는 그 문구가 **없는**
조건에서 측정됐다. 넣은 채로 비교하면 두 변수가 다르다 — 재려는 것을
직접 누르는 문구다.

⚠️ **이 논거는 1차 실행 전에도 유효했고, 실행 후에 알아챘다.** 그 사실을
기록한다. 결과를 보고 프롬프트를 무르게 한 것이 아니라, 비교 설계의
결함을 뒤늦게 본 것이다.

라운드당 상한은 **코드가 건다** (`--max-new-features 1`). 넘친 요구는
만들지 않되 **버리지 않고 기록한다** — "몇 건이 상한에 걸렸나" 가 관찰이다.

## 교락 1(요구 수준 상향)은 **배제했다** — LLM 0회

`needs_new_feature`("그 물리량의 **이름**") -> `physical_requirement`
("그것이 무엇인지 **한 문장**") 으로 문턱을 올린 것이 억눌렀을 수
있었다. 옛 303건을 다시 읽어 확인했다.

```
구절/문장        273/303 = 90.1%
식별자만 한 단어   30/303 =  9.9%   (split_k_parallelism_gain 류)
길이 중앙값 49자 (25% 39자, 75% 59자), 공백 포함 273/303
```

**"이름만 쓰라" 고 했는데도 90% 가 이미 문장이었다.** 문턱이 올라간
정도가 작으므로 요구 수준은 **유지한다.**

부수 확인: **옛 303건의 표 정보 누출 0/303.** Analyst 는 리포트를 다
보면서도 요구는 물리 언어로만 썼다 — 조건 1(리포트 차단)의 설계가
모델의 습관과 어긋나지 않는다.

## ★ 검정력 — 미리 계산한다

기준선 **10/56 = 17.9%** (같은 조건 F3 · 같은 모델 · r0~r1).
1차 Analyst 응답만 세고, 라운드당 5가설이면 **n = 3 x 4 x 5 = 60**.

```
기준선대로면 기대 10.7건
0건이 우연일 확률   (1-0.179)^60 = 7.5e-06     ★ 0 이면 결정적이다
```

Fisher 정확검정(양측, vs 10/56)으로:

```
관측 0~3건   p < 0.05   ->  ★ "억눌린다" 로 판정한다
관측 4건 이상 p >= 0.05  ->  기준선과 구분 불가 = 경로가 도는 것으로 본다
```

검정력(모의, n=60):

```
진짜 비율 5%  ->  유의 판정 확률 64%
진짜 비율 9%  ->  유의 판정 확률 20%    ★ 중간 억제는 못 잡는다
진짜 비율 18% ->  오탐 확률 0.4%
```

**"중간 정도 억제(9%)는 이 표본으로 못 잡는다" 를 미리 적어 둔다.**
관측이 4~7건이면 "구분 불가" 이지 "억제 없음" 이 아니다.

⚠️ 되돌아간 **2차 Analyst 응답은 빈도 계산에서 뺀다.** 옛 실행은
라운드당 Analyst 가 한 번이었다 (원칙 4). `analyst_pass` 로 구분하고,
`hypotheses.jsonl` 에 두 응답을 다 남긴다.
