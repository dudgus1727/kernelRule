# 리즈닝 수준별 성능 — 이 시험으로는 못 가른다

**재현** 전용 스크립트 없음. 정답 4개를 먼저 계산하고 `openai.responses` 를 `reasoning={"effort": ...}` 로 직접 불러 자동 채점했다. 천장 효과라 결론에 쓰지 않으므로 스크립트로 만들지 않았다.

**측정일** 2026-08-25 · `gpt-5.6-luna` / Responses API · 4문항 × 3회 반복

---

## 설계

**답을 먼저 계산해 두고 자동 채점했다.** 눈으로 읽고 판단하면 편향이 든다.
문항은 전부 **하드웨어 사실 + 산술**만으로 답이 하나로 정해진다 — 표를
보지 않는다 (§12.3b).

| 질문 | 정답 | 유도 |
|---|---:|---|
| Q1 wave 양자화 | 5.25배 | 512³/128² → CTA 16개, SM 84개 → `84/16` |
| Q2 트래픽 증폭 | 32배 | 4096/128 = 32, A 를 `tiles_n` 번 읽는다 |
| Q3 arithmetic intensity | 1.00 | `2MNK / (bytes)`, M=1 이면 B 가 지배 |
| Q4 경계 낭비 | 99.2% | `1 - 1/128` |

## ★ 이 결과를 "low 로 충분하다" 로 읽으면 안 된다

**천장 효과다.** 세 수준이 전부 만점이면 그 시험은 수준을 **못 가른 것**
이지 "차이가 없다" 를 보인 것이 아니다.

그리고 **시험한 것이 실제 과제가 아니다.**

```
시험    답이 하나로 정해진 계산. 4단계 안에 끝난다
실제    "어느 물리가 언제 지배하는지 8항으로 표현하라"
        정답이 없고, 여러 축을 저울질해야 하며, 채점은 regret 이다
```

F1 이 만든 `occupancy_headroom_loss`(스레드·레지스터·smem 한계의 **최소**로
활성 CTA 수를 유도)는 여러 제약을 동시에 보는 문제라 난이도가 다르다.

## 제대로 가르려면

실제 과제(Architect A)를 세 수준으로 돌려 regret 을 비교해야 하는데,
**시드 폭이 0.0977 이라 수준당 3시드로는 못 가른다** (D-40). 수준당 6시드
= 18실행이 필요하고 비용이 크다.

**결정: `medium` 을 쓴다.** 이 시험은 근거가 못 되고, 지시받은 값이며,
실제 과제가 시험 문항보다 어려우므로 여유를 두는 편이 안전하다.
비용이 문제되면 그때 실제 과제로 잰다.
