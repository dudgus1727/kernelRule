## 3. 커널 선택용 비용 모델 — **여기가 가장 가깝다**

| 연구 | 무엇 | ★ 안 하는 것 |
|---|---|---|
| ★★ [Chandran 외, Hardware-Aware Features for CUTLASS Kernel Selection (ETH, 2026-09-28)](https://arxiv.org/abs/2609.35587) · [코드](https://github.com/spcl/cutlass-selector) | **문제 · 기준선 · 지표가 우리와 같다** — 측정 없이 형상마다 CUTLASS GEMM config 하나를 고르고, 전수 측정한 최적 대비 regret 으로 재고, 기준선이 nvMatmulHeuristics **0.1.0.27 (우리와 같은 버전)** 이다. 피처도 같은 발상이다 — 형상 · config · GPU 상수로 미리 계산하는 하드웨어 거동 (wave 효율, 가장자리 타일 낭비, 산술 강도, L2 대비 작업 집합, smem · 레지스터 점유, 파이프라인 채움). 그 위에 학습 순위 모델 (MLP 176만 파라미터 · XGBoost 트리 916개). CUTLASS 3.x SM90 (TMA · WGMMA · cluster · Stream-K) BF16, GH200 하나. 학습 490만 측정 (593 형상 × 레이아웃 4, 그룹당 약 2,000 표본), 평가 17 형상 전수 (68 그룹, 392만 측정). 평균 regret (1 − 처리량 비, 산술평균) MLP 6.2% · XGBoost 6.4% · **nvMMH top-1 17.3%** · **Ridge 23.7%** · 분석 점수 63.7% | **피처를 사람이 설계한다** (Nsight Compute 프로파일 408개의 형상 안 상관). **산출물이 블랙박스 모델**이다 — 읽을 수 있는 규칙이 아니다. **GPU 간 이식을 재지 않는다** (GPU 하나 · 이식은 FP32 · FP8 · epilogue fusion 미세 조정뿐). 선택 지연을 재지 않는다 (그림에 "runs in milliseconds" 만). ⚠️ 그러나 **"선형 결합은 nvMMH 보다 못하고 비선형 모델이 있어야 한다"** 고 결론 낸다 — 물리 피처의 가중합인 우리 규칙에 정면으로 걸린다 (아래 §5.1). 우리 초록 제출 (2026-09-13) 뒤에 나온 동시대 연구다 |
| ★ [TileSight (2026)](https://arxiv.org/html/2607.22432v1) | **first-principles** 타일 중심 analytical GPU 성능 모델. 아키텍처당 1회 마이크로벤치로 보정. A100/H200/B200/B6000 에서 MAPE 12.35%, **재학습 없이 전이**. TileLang 후보의 95% 가지치기 | **계수를 표에서 학습하지 않는다** (물리에서 유도 + 보정). 그리고 **선택 지연을 µs 로 보고하지 않는다** — 우리가 §2 제약으로 삼는 값이 거기 없다 |
| ★ [tritonBLAS (2025)](https://arxiv.org/pdf/2512.04226) | Triton 기반 **analytical** GEMM 파라미터 선택. 런타임 탐색 없이 수식으로 정한다 | **측정에서 학습하지 않고**, **여러 GPU 전이를 평가하지 않으며**, **선택 지연을 보고하지 않는다** (본문 확인) |
| [TLP (2022)](https://arxiv.org/pdf/2211.03578) | 텐서 프로그램 튜닝용 **딥러닝 비용 모델**. Ansor 대비 탐색 16.7배 단축 | 학습 모델이라 **해석 가능하지 않고**, 배포 시 모델을 들고 다녀야 한다 |
| [Ansor / AutoTVM 계열](https://dl.acm.org/doi/fullHtml/10.1145/3650200.3656626) | 해석적 재사용 추정 + 학습 보정항, XGBoost 대리 모델 | **동적 형상·무표본 예측에 약하다**(위 문헌의 서술). 우리처럼 **표 없이 도는 닫힌 수식**을 산출물로 내지 않는다 |
| [WaveTune (2026)](https://arxiv.org/pdf/2604.10187) | wave 인지 bilinear 모델링으로 커널 오토튜닝 | 오토튜닝 루프 안의 모델이다. **전이를 GPU 넷에서 재지 않는다** |

## 5. ★ 우리가 다른 넷

```
1. 정답을 안다
   전수 측정 표라 "진짜 최적" 이 있다. FunSearch 계열의 평가자는 검증기이고,
   커널 생성 계열의 평가자는 실측이지만 **후보 전체의 순위를 모른다**.
   -> regret@k · 정답 집합 · 상위권 tau 를 정의할 수 있다

2. 배포 제약이 형태를 정한다
   µs 안 · 표 없이 도는 닫힌 수식 · 파라미터 8개.
   ⚠️ 그 제약에 **우리 숫자를 이제야 넣었다** — 규칙 평가 297 µs,
   지금 구현 전체 13 ms, 벤더 46 µs (select-cost.md). 위 어느 연구도
   선택 지연을 µs 로 보고하지 않는다 (TileSight·tritonBLAS 본문 확인)

3. 전이를 쟀다
   GPU 넷 · 여섯 쌍 · 열두 방향에서 (a) 완전 이식 / (b) 재적합 / (c) 재생성을
   갈랐다 (transfer-twelve.md). TileSight 는 전이를 재지만 **학습 계수가
   없어서** (b) 라는 팔이 아예 없다

4. 조건 오염을 체계적으로 막았다
   원칙 40개 · 실험 계획서 선등록 · 정정 이력 보존 · 생성물로서의 표.
   ⚠️ 이것은 **방법론 주장이지 성능 주장이 아니다**
```

### ⚠️ 정정 — Chandran 외 (2026-10-29) 에 비춰 다시 본 넷

옛 문장은 지우지 않는다. 그 논문 하나에 대해 각 항목이 어떻게 되는지만 적는다.

```
1. 정답을 안다          ⛔ 그 논문에 대해서는 차이가 아니다. 평가 17 형상을 전수 측정했다
                          (68 그룹 · 392만 측정) — 진짜 최적 대비 regret · top-1 · 5% 안 비율을 낸다.
                          학습 쪽은 그룹당 약 2,000 표본이라 전수가 아니다 (우리는 학습 형상도 전수)
2. 배포 제약            ⚠️ 약해진다. "µs 안" 은 우리 구현 전체 (13 ms) 로는 성립하지 않는다 —
                          벤더 46 µs 가 280배 빠르다 (select-cost.md). 그 논문도 지연을 재지 않았다.
                          안전한 차이는 속도가 아니라 "읽을 수 있고 표 없이 도는 닫힌 수식" 이다.
                          "파라미터 8개" 도 지금은 아니다 — D-199 최종 규칙의 가중치는 fold 당 3~18 개
3. 전이를 쟀다          ✓ 그대로. 그 논문은 GPU 하나 (GH200) 에서 정밀도 · epilogue 로만 옮긴다
4. 조건 오염            (그대로 — 방법론 주장)
```

### 5.1 ⚠️ 그 논문이 우리에게 거는 질문

같은 종류의 피처에 **비선형 모델**을 올리면 nvMMH 를 크게 이기고 (6.2 · 6.4% 대 17.3%), **선형 회귀**는
nvMMH 보다 못하다 (23.7%). 리뷰어가 "왜 XGBoost 를 쓰지 않나" 를 물을 근거다.

```
우리 기록도 정확도만 보면 같은 방향   conclusion.md 의 "벽" — 선형 결합으로는 상위 순위를 못 맞춘다.
                                      같은 피처의 GBDT 1.019 · 규칙 1.0650 · 벤더 1.0737
                                      (예전 표 — 지금 절차와 다르다)
그래도 그 Ridge 가 우리 규칙은 아니다  Ridge 는 형상별 최고로 나눈 처리량을 모든 형상에 걸쳐 MSE 로
                                      맞췄다. 우리는 시간 본항을 뼈대로 두고 형상 안 선택 (regret) 에
                                      Nelder-Mead · CMA 로 직접 맞춘다
⛔ 숫자를 나란히 두지 마라           regret 정의 (1 − 처리량 비의 산술평균 대 시간 비의 기하평균),
                                      후보 공간 (SM90 3.x · 그룹당 약 6만 대 2.x · 형상당 3,500~40,000),
                                      GPU, 형상이 다 다르다 (D-31)
```

→ **D-200** 에서 그 피처와 XGBoost (그리고 Ridge) 를 **우리 표 · 우리 fold · 우리 채점 함수**로 그대로
돌려 같은 절차로 견준다.
