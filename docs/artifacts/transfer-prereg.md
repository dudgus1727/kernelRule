# 사전 등록 — §29.5 구조 전이 (5090) (2026-08-29)

> **★ 5090 표를 보지 않고 썼다.** 표가 오면 그대로 실행한다
> **선행** `python3 experiments/transfer_check.py <번들> --env-hash <해시>`
> — 겹침을 먼저 본다. **전이 수치보다 먼저다**
> **모델** LLM 호출은 (c)에만. `DEFAULT_MODEL` 고정
> **표** A6000 dev-cu124 + 5090. **성능 수치를 인용하지 않는다**

## 무엇을 묻는가

**"A6000 에서 진화한 규칙의 구조가 5090 으로 옮겨지는가."**

이것이 이 프로젝트의 주장 중 유일하게 **다른 표로만 검증되는** 것이다.
같은 표 안에서 재는 것(홀드아웃)은 이미 다 했다.

## 세 팔

```
(a) 완전 이식   구조 + A6000 가중치 그대로 -> 5090 에서 채점
                ★ LLM 0회. 가장 강한 주장이고 가장 지기 쉽다
(b) 재적합      구조 고정, 5090 표본 5% 로 가중치만 다시
                ★ LLM 0회. "구조는 지식, 가중치는 보정" 이 맞는가
(c) 재생성      5090 표에서 처음부터 (2단계 씨앗부터)
                ★ LLM 호출 필요. (a)(b)의 천장을 준다
```

**비교 대상은 벤더**(`nvMatmulHeuristics`)다. 5090 지원 여부를 먼저
확인하고, 안 되면 **다른 기준선을 미리 정한다** — 결과를 보고 고르면
안 된다.

```
벤더가 되면    벤더 nearest
안 되면        ★ 5090 에서 재적합한 physics_seeded (b 계열의 사람 기준선)
```

## 표본과 절차 — A6000 정준 절차를 그대로

```
SOL 2분할(대리 지표) -> 체제마다 가중치 따로 -> 체제별 평가 후 결합
홀드아웃  각 체제 안에서 SOL 순 3개마다 1개
★ 5090 의 SOL 은 5090 의 하드웨어로 계산한다 — A6000 SOL 을 쓰지 않는다
```

⚠️ **바운드 뒤집힌 형상을 포함/제외 양쪽으로 낸다.** ridge 가 1.35배
움직여 체제 판정이 바뀌는 형상이 있다(A6000 격자 기준 5개, 학습 41 중
3개). 어느 쪽이든 **한쪽만 내면 고른 것이 된다.**

## ★ 검정력 — 5090 시드 폭을 먼저 잰다

```
A6000 시드 폭 σ = 0.0124 (단일 조건)를 5090 에 그대로 쓰지 않는다.
5090 에서 (c) 3시드를 돌려 σ 를 재고, 그 값으로 판정선을 정한다.
★ 그 전에는 (a)(b)의 차이에 유의성을 붙이지 않는다.
```

**이것이 이 사전 등록에서 유일하게 "표를 보고 정하는" 부분이고,
그것이 무엇인지 지금 적어 둔다** — 판정선의 *숫자*는 나중에 정하지만
**판정선을 정하는 방법**은 지금 고정한다.

## 판정 — 미리 적는다

```
(a) 완전 이식이 5090 기준선을 이긴다
    ★ "구조가 하드웨어를 넘는다" 의 가장 강한 증거
(a) 는 지고 (b) 재적합이 이긴다
    ★ "구조는 전이되고 가중치는 하드웨어 상수다" — 이것이 §29 의 가설이다
(b) 도 지고 (c) 재생성만 이긴다
    ★ 구조도 하드웨어 의존이다. 파이프라인은 여전히 값을 하지만
      "전이되는 지식" 주장은 철회한다
셋 다 진다
    ★ 그것도 결과다. A6000 에서의 성적이 그 표에 맞춘 것이었다는 뜻이다
```

**어느 경우에도 실행을 버리지 않는다.** 그리고 **A6000 결과를 지우지
않는다** — 전이 실패가 A6000 결과를 무효로 만들지는 않는다.

```
[ ] A6000 σ 로 5090 유의성을 판정하지 않는다
[ ] 5090 최종 분할을 열지 않는다 — A6000 과 같은 봉인 규칙 (§30.15)

```

# 부칙 — 세 쌍으로 넓힌다 (2026-08-31)

> **★ 무엇을 보고 썼나** 5090 번들의 `BUNDLE.json` 과 겹침 보고
> (`transfer_check`), 그리고 4090 의 예고 ridge 159.9.
> **★ 전이 성능 수치는 하나도 안 봤다.** (c) σ 측정이 도는 중이고 그
> 결과도 아직 없다.
> **왜 지금** 4090 표가 온 뒤에 설계하면 A6000↔5090 만 재 놓고 다시
> 돌려야 한다. 위 본문의 세 팔 (a)(b)(c) 는 **그대로**고, 여기서는
> **쌍**만 늘린다.

## 왜 쌍을 늘리나

위 본문은 A6000 → 5090 하나만 잰다. 그런데 그 쌍에서는 **두 가지가
동시에 바뀐다.**

```
하드웨어 규모   SM 84 -> 170,  대역폭 2.42배,  f16 1.79배
★ ridge        159.1 -> 117.9 (0.74배)  -> 체제 분류가 뒤집힌다
```

**"전이가 안 된다" 가 나와도 둘 중 무엇 때문인지 못 가른다.**

4090 이 그것을 가른다 — ridge 가 A6000 과 **0.5% 차이**다.

| 쌍 | ridge | 성격 |
|---|---|---|
| A6000 → 4090 | 159.1 → 159.9 | ★ **순수한 하드웨어 규모** 전이 |
| A6000 → 5090 | 159.1 → 117.9 (1.35배) | 규모 + 체제 뒤집힘 |
| 4090 → 5090 | 159.9 → 117.9 (1.36배) | 규모 + 체제 뒤집힘 |

## ★ 미리 계산해 둔다 — A6000↔4090 은 뒤집힘이 0일 것이다

A6000 66형상의 산술 강도 중 **`[159.1, 159.9)` 구간에 드는 것이 0개**다
(그 근방의 값은 170.7 하나뿐이다). 그래서:

```
메모리 바운드 형상 수 (A6000 격자)
  ridge 159.1 (A6000)   20 / 66
  ridge 159.9 (4090)    20 / 66     ★ 같다
  ridge 117.9 (5090)    15 / 66
```

**⚠️ 이것은 A6000 격자 위의 계산이다.** 4090 표의 형상 격자가 다르면
공통 집합이 달라진다. **표가 오면 `transfer_check` 로 다시 센다** —
0이 아니면 "깨끗한 쌍" 이라는 전제가 깨진 것이고 그때 적는다.

## 판정 — 미리 적는다

```
A6000 -> 4090 에서 (a)/(b) 가 된다   그리고
A6000 -> 5090 에서 안 된다            ★ 원인은 ridge/체제다.
                                       셀 축과 체제 축을 다시 봐야 한다

둘 다 안 된다                         ★ 원인은 하드웨어 규모다.
                                       ridge 는 범인이 아니다

둘 다 된다                            ★ 구조가 하드웨어를 넘는다.
                                       §29 의 가장 강한 형태
```

⚠️ **"4090 에서는 되고 5090 에서 안 된다" 를 ridge 탓으로 바로 읽지
않는다.** 5090 은 세대도 다르다 (Blackwell). 4090 은 Ada 이고 A6000 은
Ampere 이므로 A6000→4090 도 세대를 건넌다 — 그것이 이 쌍의 값어치다.
그래도 sm_86→sm_89 와 sm_86→sm_120 은 거리가 다르다. **가르는 것은
ridge 하나가 아니라 "ridge 를 뺀 나머지가 같은 방향인가" 다.**
