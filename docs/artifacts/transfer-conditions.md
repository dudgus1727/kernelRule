## 1. 두 표는 같은 격자가 아니다

| | A6000 (sm_86) | 5090 (sm_120) | 통제 |
|---|---|---|---|
| 세대 | Ampere | Blackwell | ❌ 이것이 실험 대상이다 |
| SM 수 | 84 | (표에서 읽는다) | ❌ |
| 실효 대역폭 | 729.7 GB/s | (표) | ❌ |
| 실효 f16 | 116.1 TFLOP/s | (표) | ❌ |
| **ridge** | **159.1** | **117.9 (예고값)** | ❌ **1.35배** |
| 형상 격자 | 66 (5층) | 66, **값이 다르다** | ⚠️ 교집합만 |
| split_k 축 | 7종 실측 (1,2,3,4,6,8,16) | **10종** | ⚠️ 교집합만 |
| 눈금 | 1.024 µs | 32 ns | ❌ |

**아래 다섯 층 중 층 B(M 상향)와 층 E(사다리 이동)가 달라진다고 예고됐다.**

```
a_workload 40 / b_kvary 12 / c_waves 11 / d_alignment 5 / e_square 5
```

## 2. ★ ridge 가 1.35배 움직이면 체제가 뒤집힌다

**A6000 형상으로 미리 계산했다** (5090 ridge 를 117.9 로 가정).

```
메모리 바운드 형상 수   A6000 22/66  ->  5090 17/66
★ 뒤집히는 형상 5개 (학습 41 안에서는 3개)
   512x512x512      AI 128.0
   128x11008x4096   AI 119.2
   128x4096x11008   AI 121.4
   128x4096x16384   AI 122.3
   128x12288x4096   AI 119.3
```

**전부 AI 119~128 구간**이다. 두 ridge 사이에 낀 좁은 띠다.

### 왜 중요한가

체제별로 **가중치를 따로 적합한다**(§10, §29). 체제 판정이 표마다
다르면 같은 형상이 A6000 에서는 "긴/메모리" 쪽 가중치로, 5090 에서는
"짧은/컴퓨트" 쪽 가중치로 채점된다.

```
조용히 넘어가면
  "전이가 안 됐다" 가 사실은 "다른 것을 비교했다" 일 수 있다
```

⚠️ **이 5개는 예고된 ridge 값 기준이고 실제 격자도 다르다.** 표가
오면 `bound_flipped` 로 다시 센다.

## 3. config 동일성 — 축 좌표로만 정한다

`kernel_id` 는 아키텍처마다 다르게 컴파일된다. `regs_per_thread` /
`smem_bytes` / `spill_bytes` / `max_blocks_per_sm` / `inst_total` 도
**빌드 결과**라 GPU 가 바뀌면 달라진다.

```
축 좌표 = tile_m, tile_n, tile_k, split_k, split_k_mode, align_a/b/c
A6000 축 좌표 수 1,634 (형상당)
```

⚠️ **"같은 config" 가 아니라 "같은 축 좌표" 다.** 같은 타일 축이라도
세대별로 다른 명령어를 쓴다. 이 구분을 안 하면 "같은 커널이 전이됐다"
로 과장된다.

`pipeline_kind` 는 **넣지 않았다** — 세대마다 이름이 달라질 수 있다.
표가 오면 값 집합을 대조하고, 같으면 넣을지 그때 판단한다(그리고
그 판단을 기록한다).

## 4. 통제하지 못하는 것 — 정리

```
❌ 못 한다   세대 / SM 수 / 대역폭 / 연산 성능 / ridge / 눈금 / 노이즈
             ★ 이것이 실험 대상이다. 통제하면 실험이 없다
⚠️ 교집합    형상 격자 / config 축
             ★ 버린 양을 반드시 센다 (`CrossReport.render`)
✅ 같다      규칙 코드 / 피처 정의 / 채점 절차 / 적합기 / 모델
             ★ 규칙과 피처는 `cfg.ext` 를 안 쓰므로 그대로 돈다 (§4.3)
```
