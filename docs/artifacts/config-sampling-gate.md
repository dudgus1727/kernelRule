## 통과 조건 1 — (a) 규칙의 상위 k% 에 정답이 드는가

5090 홀드아웃 20형상, 후보 중앙 20,790개, 정답 집합 중앙 11개.

### 정답 집합 원소가 상위 k% 에 **하나라도** 드는 형상 비율

```
              0.5%     1%     2%     5%    10%
(a) 6구조    5~30% 15~30% 25~40% 30~55% 45~80%     중앙 5% 에서 45%
★ 무작위       12%    24%    33%    47%    62%     (뽑기 20번 평균)
정적(A6000)     0%     0%     5%    30%    40%
```

**(a) 가 무작위와 같다.** 커버리지에서 규칙이 주는 이득이 없다.
정적(이전 GPU 의 고정 config)은 **무작위보다 나쁘다.**

### **진짜 최적**이 상위 k% 에 드는 형상 비율

```
              0.5%     1%     2%     5%    10%
(a) 6구조     0~15%  0~15% 10~20% 15~40% 25~60%
무작위          0%     1%     2%     6%    11%
정적            0%     0%     5%    20%    30%
```

**여기서는 (a) 가 무작위의 3~7배다.** 순위 신호는 분명히 있다.

### 왜 두 지표가 달라지나 — 정답 집합 크기가 극단적이다

```
홀드아웃 20형상의 정답 집합 크기
[1, 1, 1, 1, 2, 4, 5, 6, 9, 10, 13, 14, 14, 28, 34, 47, 77, 92, 228, 464]
```

**4형상은 2만 후보 중 정답이 1개**다. 464개짜리 형상은 아무렇게나 뽑아도
맞는다. "정답 집합 적중" 은 큰 형상에서 우연이 지배하고, "진짜 최적
적중" 은 작은 형상에서만 달라진다.

### 무작위만으로 몇 % 를 재야 하나

```
config%    정답집합 적중    진짜 최적 적중
    1%          24%            1%
    5%          47%            6%
   10%          62%           11%
   30%          81%           32%
   50%          88%           50%
```

**50% 를 재도 90% 에 못 닿는다.** 정답이 1개뿐인 형상이 있어서 구조적으로
그렇다.

### 판정

미리 정한 기준은 **"상위 5% 에 90% 이상이면 쓸 만하다"** 였다.
**어느 팔도 못 넘는다.** 무작위를 50% 까지 올려도 88% 다.

⚠️ **다만 이 통과 조건이 죽이는 것은 한 가지 용법뿐이다.**

```
"5% 만 재고 그 안에서 고른다"              ★ 죽는다. 5% 든 50% 든 안 된다
"5% 로 가중치만 맞추고 전수를 순위 매긴다"   ★ 이 통과 조건이 답하는 질문이 아니다
```

⛔ **벤더는 못 쟀다.** `nvMatmulHeuristics` 가 이 환경에 없다 (import
실패). **"없다" 를 "나쁘다" 로 적지 않는다.**

## 통과 조건 2 — ★ 순위 손실이 목표와 어긋나는가

config 를 일부만 재면 `regret` 을 못 쓴다(최적을 모른다). 대리로 순위
손실을 쓸 수 있는지를 **config 전수**로 먼저 잰다 — 샘플링 변수를
섞으면 무엇이 원인인지 못 가른다.

### 설계에서 지킨 것 셋

```
1 양성은 참 상위 32개, 음성은 순위 구간별로 고르게 256개
  — 15,000등과 16,000등의 순서는 안 센다
2 ★ 노이즈 바닥으로 못 가르는 쌍은 뺐다 (`NoiseModel.resolvable`)
3 ★ T = 1 고정. s = Φw 로 w 에 선형이므로 w 를 c 배 하면 s 가 c 배다 —
  T 는 w 크기와 **분리해서 식별되지 않는다.** T 를 두는 것은 자유도를
  늘리는 게 아니라 중복시키는 것이라, T=1 은 선택이 아니라 정규화다
```

`fit_weights` 는 안 건드렸다 (채점 뜨거운 경로). 실험 스크립트 안에서
L-BFGS-B 로 따로 푼다. 선형성은 구조마다 확인했다 — 6/6 통과.

### 결과 — 6/6 이 나쁘다

```
구조                     A) 순위손실   B) regret       A-B
f1pipe-F3-arch24-s0        1.1078      1.0657    +0.0421
              s1           1.0531      1.0455    +0.0076
              s2           1.0923      1.0804    +0.0119
              s3           1.0640      1.0564    +0.0076
              s4           1.0693      1.0513    +0.0180
              s5           1.1456      1.0441    +0.1014

중앙  A) 1.0808   B) 1.0539   차이 +0.0269
★ 대응 Wilcoxon 양측 p = 0.0312   (6/6 이 A 가 나쁘다)
참고: 비대응 판정선(σ 상한) 0.0516
```

### ★ 최적화 실패가 아니다 — 확인했다 (원칙 11)

```
12/12 (구조 6 x 체제 2) 수렴  success=True
손실 감소   13.70 -> 0.21,  5.78 -> 0.21,  2.04 -> 0.05 ...
|dw|/|w0|   0.6 ~ 29.2      ★ 초기값에 안 머문다
```

**순위 손실은 잘 최소화된다. 그런데 그 가중치가 top-1 regret 에서는
더 나쁘다.** 대리 손실과 목표가 실제로 어긋난다.

기전도 보인다. 최종 손실이 0.02~0.24 로 **적합 집합의 쌍 순서는 거의
완벽**한데, `regret` 은 **1등 하나**만 본다. 쌍 손실은 쉬운 쌍(상위 32
대 1만등)이 개수로 지배하고, 목표는 어려운 쌍(1등 대 2등)에만 달려 있다.

### 판정

미리 정한 것: *"비슷하다 → §4 로 간다 / 크게 나쁘다 → 여기서 멈춘다."*

**6/6 이 같은 방향이고 p = 0.0312 다. "비슷하다" 가 아니다.**
크기(+0.0269)는 비대응 판정선의 절반이라 "파국" 도 아니지만,
**통과 조건은 통과 못 했다. 멈춘다.**

⚠️ **이것은 이 구현에 대한 결과다.** 쌍 구성(상위 32 / 층화 256)과
T=1 은 하나의 선택이고, 상위끼리의 쌍에 집중하는 설계는 다를 수 있다.
**그러나 결과를 보고 고쳐 다시 돌리지 않는다** (§12.3d) — 고치려면
새 실험 계획서가 필요하다.
