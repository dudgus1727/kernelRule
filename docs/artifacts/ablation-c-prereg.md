## 무엇을 묻는가

D-89 는 "Analyst 가 기여한다" 를 보였지만 **어느 부분이 기여하는지는 안
갈랐다.**

```
진단 리포트의 내용인가        이 라운드의 상태에 맞는 방향인가
아니면 그냥 다양성 주입인가   매 라운드 다른 문장이 들어오는 것 자체인가
```

**C 는 Analyst 를 안 부르고 남의 가설을 넣는다.** 문장은 진짜 Analyst 가
쓴 것이지만 **이 라운드의 상태와는 무관**하다.

```
C 가 B 에 가까우면   가설이 현재 상태에 맞을 필요는 없다
                    = 진단 리포트의 기여가 **다양성 주입**이다
C 가 A 에 가까우면   ★ 이 라운드의 진단에 맞아야 한다
                    = §16.1 의 강한 형태가 성립
```

## 어떻게 빌리나 — **묶음 단위**

```
(실행, 라운드) 단위로 통째로 가져온다. 낱개로 섞지 않는다.
```

**낱개로 섞으면 다른 실험이 된다.** Analyst 한 번의 출력은 서로를
보완하는 집합이고, 낱개로 섞으면 "맞지 않는 가설" 이 아니라 **"앞뒤가 안
맞는 묶음"** 이 된다. 묶음이면 라운드당 개수 분포도 B 와 자동으로 같다
(평균 4.4개).

```
★ 같은 시드 번호의 실행은 뺀다 — abl-B-s1 을 abl-C-s1 에 주면
  "다른 실행" 이 아니다
★ 풀이 비면 **예외**를 낸다 — 조용히 가설 없이 돌지 않는다 (§26.4)
★ 빌린 가설에 `borrowed_from` 을 남긴다
```

## 프롬프트 — 절 구조는 B 와 같다

```
Analyst 는 안 부른다 (호출 수는 A 와 같다)
★ 그러나 가설 절은 **렌더링한다**
```

A 와 프롬프트 구조까지 같게 만들면 **C 가 A 의 복제가 된다.** C 의
차이는 **문장의 출처뿐**이어야 한다.

⚠️ A 때 쓴 **부분수열 검사는 여기 못 쓴다** (C 는 B 에서 지운 것이
아니라 내용만 바꾼 것이다). 대신 `test_borrowed_arm_calls_no_analyst_but_
renders_the_section` 이 "Analyst 호출 0 + 가설 절 있음" 을 고정한다.

## ★ 주 지표는 성능이 아니라 **중복률**

D-89 에서 중복률이 성능보다 민감했다.

| | 채점된 제안 비율 |
|---|---|
| B (Analyst) | 84% · 90% · 92% |
| A (없음) | 28% · 53% · 47% |

```
C >= 80%   ★ 다양성만으로 충분하다 (진단의 기여가 다양성 주입)
C <= 60%   ★ 내용이 맞아야 한다 (§16.1 의 강한 형태)
그 사이     구분 불가. 그것도 결과다
```

**경계를 A 상한(53%)보다 위, B 하한(84%)보다 아래로 잡았다.**
C 가 A 범위 안에 들어오면 애매해지므로 60% 를 아래 경계로 둔다.

## ★ 함께 보는 것 — 조기 정체

```
검증이 마지막으로 개선된 라운드   B r9 r7 r8    A r2 r3 r4    C ?
```

**이것이 조기 정체의 원인을 가른다.**

```
C 가 늦게까지 개선   중복이 원인이었다 — 다양성이 그것을 푼다
C 도 일찍 정체      방향이 원인이다 — 맞는 가설이 필요하다
```

**중복률과 같은 방향이면 결론이 단단해진다.** 두 지표가 달라지면 그 사실을
그대로 적고 결론을 내지 않는다.
