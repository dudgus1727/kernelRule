## 1. ★ 요구율이 기준선으로 돌아왔다

표본 하나 = 실행 하나 (원칙 28). 1차 Analyst 만, r0~r3.

| | 실행별 요구율 | 중앙 |
|---|---|---:|
| 기준선 `arch24` | 12.5 22.2 20.0 23.5 16.7 21.1 % | 20.5% |
| **4차 `d75run4`** (씨앗 고정) | **22.2 11.1 35.3 11.8 25.0 0.0 %** | **17.0%** |
| 3차 `d75run3` (씨앗 다름) | 0.0 5.6 0.0 0.0 0.0 5.6 % | 0.0% |

```
4차 vs 기준선   Mann-Whitney 양측 p = 0.8726   ★ 구분 불가
4차 vs 3차      Mann-Whitney 양측 p = 0.0247   ★ 다르다
```

**실험 계획서의 판정 그대로다: `p >= 0.05` -> 회복됐다 -> 누른 것은 씨앗이었다.**

⚠️ **"같다" 가 아니라 "구분 불가" 다** (원칙 27). 13% 급 차이는 이
표본으로 절반쯤 놓친다.

## 2. 씨앗 고정이 실제로 축을 되돌렸다

실험 계획서의 확인 항목 2번: "씨앗을 고정했으니 평균 f 피처 수가 기준선
범위에 들어와야 한다."

```
기준선   12.7 12.9 12.0 12.2 13.6 12.7   범위 12.0~13.6
4차     12.6 12.6 11.5 10.6 13.2 13.0   범위 10.6~13.2   ★ 겹친다
3차      8.6  8.8  7.6  8.2  8.0  7.9   범위  7.6~ 8.8   ★ 분리
```

**개입이 두 축을 함께 되돌렸다.** 상관(rho = +0.566)이 이제 **한
방향으로는 인과**다 — 씨앗을 바꾸면 요구율이 따라온다.

## 3. ★ 그러므로 D-78 과 경로는 이 크기의 억제를 만들지 않는다

4차는 **D-78 도 경로도 켜진 채**로 돌았고 요구율이 기준선과 구분되지
않았다.

```
"D-78 이 요구를 눌렀다" 는 이 자료로 **지지되지 않는다**
```

⚠️ **"무해하다" 는 아니다** (실험 계획서의 하지 말 것). 둘을 서로 못
가르고, 13% 급 억제는 이 표본으로 절반쯤 놓친다. 말할 수 있는 것은
**"기준선 범위를 벗어나게 하지는 않았다"** 까지다.

## 4. 경로 관찰

```
요구 -> 축 4개 생성 (검증 통과)
★ 상한 초과로 안 만든 요구  4건 — 기록만 하고 버렸다
되돌아간 Analyst 가 그 축을 언급  3/4
요구 문장 누출                   0/8
아카이브 사용                    1~2/5~8 규칙, 2개는 **최선 규칙**에
```

| 실행 | 라운드 | 만든 축 | 최선 규칙에 |
|---|---|---|---|
| s0 | r0 | `shared_memory_storage_overhead` | 아니오 |
| s0 | r1 | `shared_reuse_deficit` | **예** |
| s2 | r1 | `shared_bank_stride_risk` | 아니오 |
| s3 | r3 | `shared_accesses_per_output` | **예** |

### ★ 넷 다 같은 주제다 — 그리고 그것은 **금지된 축**이다

```
요구  "swizzle별 shared-memory bank-conflict 또는 접근 효율"
      "유효 출력 원소당 공유 메모리 뱅크 트랜잭션 수"
```

옛 303건에서 **가장 많이 반복된 문장(4회)이 바로 swizzle 별 bank
conflict** 였고, 그것은 `cfg.ext` 라 프롬프트가 금지한다(§4.3,
아키텍처 전용이라 전이가 안 된다).

**FeatureWriter 는 `cfg.ext` 없이 그것을 근사했다.** 타일 치수와 공유
메모리 크기로 bank stride 위험을 대신 잰다.

```
금지된 축을 요구가 계속 가리키고,
경로가 생기자 **금지되지 않은 재료로 근사물**이 만들어졌다.
```

이것이 좋은 일인지는 아직 모른다 — 근사가 실제 bank conflict 와
얼마나 맞는지는 이 표로 못 잰다. **관찰로만 남긴다.**

### 상한이 처음으로 실제로 걸렸다

```
s2 r1  문제 형상 종횡비에 대한 타일 방향 정렬도
s2 r2  레지스터와 공유 메모리의 공동 제약을 적용한 실제 resident CTA 수
s3 r3  warp-to-tile 매핑에 따른 shared-memory bank conflict
s4 r3  warp-tile Tensor Core utilization 또는 instruction-shape efficiency
```

**버리되 기록한다**는 설계가 값을 했다 — 이 넷은 라운드당 상한 1 이
아니었으면 만들어졌을 것이다. 뒤의 둘은 `cfg.ext` 계열이라 어차피
거부됐을 수도 있다.

## 5. D-78 은 세 번째 확인

```
리터럴 비교를 쓴 실행   옛 1/6  ->  새 6/6      Fisher p = 0.0152
실행별 비율            옛 0 0 0 0 0 2 %
                      새 67 38 27 60 73 33 %    ★ 겹치지 않는다
```

**씨앗이 같은데도 그렇다** — 이번 4차는 기준선과 **씨앗까지 같으므로**
리터럴 증가는 씨앗 탓일 수 없다. D-78 이 원인이라는 근거가 한 겹
두꺼워졌다.

우회(`isfinite`/`sign`)는 옛 4/6 -> 새 2/6, **p = 0.57 — 여전히 못
가린다.**
