# 실험 계획서 — `cross` 부모를 실제로 구현한다 (2026-08-31)

> **★ LLM 호출 0회 상태에서 작성했다.**
> **근거** [diversity-and-parallel.md](diversity-and-parallel.md) §4
> **모델** `gpt-5.6-luna` medium (고정) · **표** dev-cu124 · **씨앗 고정**
> **성능 수치를 인용하지 않는다** — 판정은 관찰로 한다

## 무엇이 문제인가

```
archive.parents 가 cross 에 Elite 둘을 준다     True  (rng.choice(size=2))
run_round 가 실제로 쓰는 것                     ['ps[0]']
RuleEditor 프롬프트의 부모 자리                  {parent_code} 하나뿐
```

**`cross` 는 `explore` 와 같다.** 두 부모를 뽑는 코드는 도는데 두 번째가
프롬프트에 도달하지 않는다. **§13 의 교차가 구현된 적이 없다.**

그리고 이것이 D-42 를 다시 열었다 — "앙상블이 안 듣는 것은 다양성이
표면적이라는 증거" 라고 했는데, **칸들을 합치는 경로가 아예 없었다.**
MAP-Elites 의 값어치는 칸을 채우는 것이 아니라 **합치는 것**이다.

## 설계

```
RuleEditor 프롬프트에 부모 자리를 **둘**로 (cross 일 때만)
  "두 규칙을 받아 각각의 좋은 항을 합쳐라"
  ★ 예산이 있으므로 합치면 **반드시 버려야 한다** —
    무엇을 버렸고 왜 그것을 골랐는지 `changes` 에
```

⚠️ **조건부 프롬프트는 빈 자리표시자 구멍을 만든다** (D-89 에서 밟았다).
그래서 §16.1 때와 같은 규율을 쓴다 — **두 번째 부모가 없으면 그 절
자체를 안 만든다.** `exploit`/`explore` 의 프롬프트는 **지금과 문자
단위로 같아야 하고** 시험으로 고정한다.

## ★ 판정 — 성능이 아니라 관찰로

3시드로는 성능을 못 가린다 (시드 폭 0.0124, 최소 가능 p = 0.10).

```
1  ★ cross 산출물이 두 부모의 항을 실제로 섞는가
   지표: 자식이 쓰는 f 피처 중 **부모 A 에만 있던 것**과 **부모 B 에만
        있던 것**을 둘 다 포함하는 비율
   기준: >= 40% 면 섞고 있다 / <= 10% 면 한쪽만 베낀다
        (섞을 항이 없는 경우가 있으므로 100% 를 기대하지 않는다)

2  아카이브 셀 점유가 늘어나는가
   지금 5~11칸. cross 가 두 칸을 잇는 자식을 만들면 늘어야 한다

3  ★ 앙상블이 통하기 시작하는가 — D-42 재시험
   상위 k개 순위 평균의 폭과 중앙. 옛 관측은 폭 0.098 -> 0.100,
   중앙 1.0817 -> 1.1137 (안 들었다)
   ★ 이것이 "결합 경로의 부재" 가설의 직접 시험이다

4  cross 의 중복률 — `by_parent_kind` (D-94 로 이제 기록된다)
   지금은 못 쟀다. 두 부모를 주면 중복이 줄어야 한다
```

**성능은 부차 지표로만 적는다.**

## 표본

```
씨앗 고정  --seed-from runs/f1pipe-F3-arch24   (D-88)
3시드 x 12라운드,  ★ 병렬화 뒤라 약 1시간 (전에는 5시간)
비용 약 470호출
표본 단위 = 실행 (원칙 28). 3 대 3 은 유의성을 못 낸다 — 범위로 본다
```

**대조군은 지금 코드다** (`abl-B` 3실행, 같은 씨앗·같은 프롬프트).
`by_parent_kind` 가 그때는 없었으므로 **4번은 새 실행끼리만 비교한다.**

## 공유되는 것 (원칙 28)

| 층 | 항목 | 대조군과 같은가 |
|---|---|---|
| 모델 · 표 · 분할 | | ✅ |
| 캠페인 | 2단계 씨앗 | ✅ `--seed-from` |
| 캠페인 | 라이브러리 · 예산 · 경로(끔) | ✅ |
| 캠페인 | Analyst | ✅ 켬 |
| 캠페인 | **cross 프롬프트** | ❌ **이것만 다르다** |
| 실행 | 시드(RNG) | ❌ 표본 축 |
| — | 배정 무작위화 (D-94) | ⚠️ **대조군에는 없다** |
| — | 병렬화 (D-95) | ✅ 값이 같으므로 조건이 아니다 |

⚠️ **D-94 가 교락이다.** `abl-B` 는 라운드로빈 배정이었다. 그래서
**성능 비교는 하지 않고** 1~4번 관찰만 쓴다 — 그 넷은 배정 방식과
직접 얽히지 않는다.

⚠️ 병렬화는 **값이 같음을 시험으로 고정**했으므로 조건이 아니다
(`test_parallel_matches_sequential`).

## 판정 — 미리 적는다


**어느 경우에도 실행을 버리지 않는다.**
