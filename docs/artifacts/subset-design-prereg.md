# 사전 등록 — 표본 크기가 문제인가 표본 **선택**이 문제인가 (2026-09-01)

> **★ 설계된 부분집합 실험을 돌리기 전에 썼다.** LLM 호출 0회 (전 팔 0회)
> **선행 결과** [refit-sample.json](refit-sample.json) — 무작위 층화 뽑기
> **표** 5090 `5bb6f403` · **구조** A6000 F3 6시드의 학습 최고 6개
> **재현** `python3 experiments/subset_design.py --workers 6`

## 무엇을 묻는가

무작위 층화 뽑기에서 **k=4 (9.8%) 가 8번에 1번 파국**이었다 (홀드아웃
> 1.15, 최악 2.35). 그래서 "30% 는 있어야 한다" 로 읽었다.

**그런데 실무에서는 안 건다 — 고른다.**

```
지금 실험   체제별 층화 + ★ 그 안에서 무작위
실무        새 GPU 에서 "어느 형상을 잴까" 를 ★ 우리가 정한다
```

형상 그리드 설계는 kernelTab 이 매 캠페인 하는 일이다. **무작위 뽑기는
최악의 경우를 재고 있다.**

## ★ 쓸 수 있는 것과 없는 것 — 이것이 이 실험의 경계다

새 GPU 에서 **표를 재기 전에** 계산할 수 있는 것만 쓴다. 표 유래 값을
쓰면 그 자체가 누출이고, 그러면 "표 없이 고른다" 는 시나리오가 깨진다.

```
쓸 수 있다
  SOL 하한            형상 + 하드웨어 상수만
  arith_intensity     마찬가지 (형상만의 함수)
  ridge 대비 위치     체제 경계에서 얼마나 떨어졌나
  M/N/K 비율과 절대 크기
  kernelTab 의 층 라벨 (a_workload / b_kvary / c_waves /
                        d_alignment / e_square)  — BUNDLE.json 에 있다

★ 쓸 수 없다
  난이도(difficulty) / best_ms / distinct_time_frac / answer_mask 크기
  — 전부 표를 재야 안다. `ANSWER_COLS` 계열이다
```

⚠️ 5090 학습 41형상의 층 분포: `a_workload` 20 / `b_kvary` 12 /
`c_waves` 12 / `e_square` 4 / `d_alignment` **0**.
`d_alignment` 는 정렬 8 필터에서 전부 빠진다 — **"층 균등" 은 4층
균등이다.** 이것을 모르고 5층으로 나누면 한 층이 조용히 빈다.

## 후보 전략 셋

```
(1) SOL 로그 균등   각 체제 안에서 log(SOL) 분포를 고르게 덮는다
                   ★ 분위수로 나누고 각 칸의 중앙에 가장 가까운 것
(2) 경계 포함       ridge 대비 위치가 1에 가까운 형상을 반드시 포함
                   ★ 거기가 분류가 뒤집히는 자리다
(3) 층 균등         a/b/c/e 네 층에서 고르게
```

**(1)+(2) 를 먼저 재고, 필요하면 (3) 을 더한다.** 셋을 한꺼번에 내면
어느 것이 들었는지 못 가른다.

## 실험 설계

```
같은 k 에서 두 팔
  무작위 층화     ★ 이미 있다 (refit-sample.json)
  설계된 부분집합  결정론적이면 뽑기 1번

k = 2, 4, 8, 10, 12        (파국이 있던 구간 + 꼭짓점)
구조 6개
★ 설계 팔은 뽑기 운이 없다 — 그것이 요점이다
   동률로 결정이 안 되면 그 안에서 10번 뽑고 그 사실을 적는다

홀드아웃은 언제나 20형상 전부
★ LLM 0회. 재적합만 다시 돌린다
```

## ★ 주 지표 — 중앙값이 아니다

```
주   파국 비율 (홀드아웃 > 1.15)
보조 최악 손실 / 중앙 손실 / 폭
```

**중앙값을 주 지표로 쓰면 안 된다.** 무작위 팔에서 k=4 의 중앙 손실은
+0.0276 인데 최악이 +1.29 였다 — 중앙만 보면 "10% 면 된다" 가 나온다.

## 판정 — 미리 적는다

```
설계 팔의 파국 비율이 0 이고 k <= 8 에서도 그렇다
  ★ "몇 % 가 아니라 어떻게 뽑나" 가 답이다
  비용 주장이 회복된다 (30% -> 10% 이하)

설계 팔이 무작위와 비슷하다
  ★ 형상 수 자체가 부족하다. 30% 가 맞다
  그리고 그 경우 "형상/파라미터 비" 가 단위라는 쪽이 강해진다

설계 팔이 무작위보다 나쁘다
  ★ 그대로 적는다. 설계가 특정 축에 쏠려 홀드아웃을 못 덮었다는 뜻이고
    그것도 결과다
```

## 예상 — ★ 열린 질문이다

설계가 나을 것 같지만 **안 나을 수도 있다.** 형상 2개로 가중치 8개를
정하는 것은 어떻게 골라도 과소결정일 수 있다. `k=2` 에서 설계가 안
들으면 그것이 "선택이 아니라 크기" 라는 증거다.

## 공유되는 것 (원칙 28)

| 층 | 항목 | 두 팔이 같은가 |
|---|---|---|
| 표 · 분할 · 홀드아웃 | | ✅ |
| 구조 6개 | A6000 F3 6시드 | ✅ 같은 것 |
| 적합기 | Nelder-Mead 300 + 다듬기 | ✅ |
| 체제 판정 | 5090 하드웨어로 | ✅ |
| **뽑는 방법** | 무작위 층화 vs 설계 | ❌ **이것만 다르다** |
| 뽑기 운 | 무작위 10번 vs 설계 1번 | ⚠️ **비대칭이다 — 아래** |

⚠️ **표본 수가 두 팔에서 다르다.** 무작위는 k마다 60건(구조 6 x 뽑기
10), 설계는 6건(구조 6 x 1)이다. **파국 비율을 견줄 때 이것이 분모다** —
설계 팔에서 6건 중 0건은 "파국률 0" 이 아니라 **"0/6, 95% 상한 39%"**
다 (원칙 27). 그 상한을 함께 적는다.
