## A. `k` 스윕 — 상위 몇 개까지 볼 것인가

### 판정선이 걸린 칸 (regret 재적합, tau 는 k=100 고정)

```
              regret   상위100 tau     전구간   (tau 범위)
k=10          1.1365       0.081      0.205   +0.025~+0.161
k=20          1.1151       0.144      0.272   +0.078~+0.264
k=50          1.1270       0.026      0.415   -0.006~+0.111
k=100 (기존)   1.1213       0.115      0.267   -0.021~+0.155
★ 무작위 바닥   1.8753      -0.007      0.000
```

**네 값의 범위가 전부 겹친다. 어느 `k` 도 벽을 안 움직인다.**

### 순위 적합 (그 팔의 k 로 맞춘다)

```
              regret   상위100 tau     전구간
k=10          5.3957       0.174      0.206
k=20          1.5829       0.235      0.141
k=50          2.0906       0.327      0.056
k=100 (기존)   1.6364       0.353      0.320
★ 무작위 바닥   1.8753      -0.007      0.000
```

★ **`k` 를 줄이면 regret 이 좋아질 것으로 기대했는데 반대다.**
k=10 은 regret 5.40 으로 **무작위 바닥(1.875)보다 3배 나쁘다.**
그리고 tau@100 도 같이 내려간다 (0.353 -> 0.174).

### A2. 그 실행의 k 로 잰 tau — 바닥이 k 마다 다르다

```
              k   상위k tau   무작위 바닥    바닥 위
k=10         10      0.264      0.002    +0.262   ⚠️ 정의 안 되는 형상 1개
k=20         20      0.372      0.005    +0.366
k=50         50      0.423      0.004    +0.419
k=100       100      0.353     -0.007    +0.361
```

**좁은 띠 안의 순서는 좁힐수록 잘 배운다** (k=50 이 0.423 으로 최고).
**그런데 그것이 밖으로 안 나간다** — 같은 규칙의 tau@100 은 0.327 로
k=100 팔(0.353)보다 낮고, regret 은 2.09 로 더 나쁘다.

⚠️ k=10 에서 **한 형상은 tau 가 정의되지 않는다** — 규칙이 그 형상의
상위 10 에 **상수 점수**를 준다. 세지 않으면 `nan` 이 중앙값을 먹는다
(처음 돌렸을 때 실제로 `nan` 이 나왔다, §5 정정).

### 판정 (사전 등록 §3-4)

```
k 가 줄수록 regret 이 좋아지면서 tau 유지   -> 벽이 낮아진다
k 가 줄면 tau 만 따라 내려간다             -> 벽이 그대로다
★ 실제:  regret 도 tau 도 같이 나빠진다   -> 벽이 그대로다 (그 이상)
```

## B. 곱 항 — 명시하면 달라지나

### ★ 먼저: 정적 검사는 **원래 곱을 막지 않았다**

지시는 "정적 검사에서 그 규칙 하나를 푼다" 였는데 **그런 규칙이 없다.**
`(f.a * f.b) * w[0]` 은 지금도 위반 0 / 경고 0 으로 통과하고, 이미
쓰이고 있었다 (전체 규칙 531개 중 312개 = 59%). 그래서 조건은
"푸는 것" 이 아니라 **"말해 주는 것"** 이 됐다.

### 말해 주니 늘었다

```
             곱 쓴 규칙    규칙당 곱
k=100 (기존)   25/38 (66%)     1.97
곱 항 명시      28/32 (88%)     2.62
```

자주 나온 쌍:

```
기존      pipeline_warmup_frac x log_mainloop_iters (11)
         tile_aspect_imbalance x traffic_amplification (9)
곱 명시    ★ reg_pressure x reg_pressure (19)   — 제곱이다
         is_two_stage x (pipeline_warmup_frac + smem_pressure) (7)
         pipeline_warmup_frac x smem_pressure (7)
```

### ★ 물리적으로 말이 되나 — 제곱이 나왔다

가장 많이 나온 것은 **곱이 아니라 제곱**이다:

```python
s = s + np.where(f.reg_pressure < 1,
                 f.reg_pressure,
                 f.reg_pressure * f.reg_pressure * f.reg_pressure) * w[2]
```

레지스터 압력이 1 을 넘으면 **3제곱으로** 벌을 준다. 이것은 읽힌다 —
스필이 시작되면 손해가 초선형으로 커진다는 것이고, `has_spill` /
`spill_magnitude` 가 이미 있는데도 **연속적인 초선형 항**을 따로
만들었다. 해석 가능성을 이유로 막았으면 안 나왔을 형태다 (§29.3b).

### 성능

```
                        regret   상위100 tau     전구간
★ regret 재적합  기존     1.1213       0.115      0.267
                곱 명시   1.1228       0.078      0.471   (+0.009~+0.091)
순위 적합       기존     1.6364       0.353      0.320
                곱 명시   1.6332       0.370      0.416   (+0.370~+0.375)
★ 무작위 바닥            1.8753      -0.007      0.000
```

**판정선이 걸린 칸은 안 움직인다** (0.115 -> 0.078, 범위 겹침).
순위 적합 쪽에서 tau 가 0.353 -> 0.370, 전구간이 0.320 -> 0.416 으로
오르고 **시드 범위가 매우 좁다** (+0.370~+0.375). 곱은 순위 능력을
조금 올리지만 **벽은 그대로다.**

## C. λ 스윕 — 두 손실의 합

`L(w) = rank_loss(k=100) + λ · rank_loss_top1(k=100)`.
`rank_loss_top1` 은 **참 1등이 낀 쌍만** — `regret` 이 아니라 그
부드러운 대리다 (사전 등록 §C).

### 판정선이 걸린 칸 (regret 재적합)

```
              regret   상위100 tau     전구간   (tau 범위)
λ=0 (기존)     1.1213       0.115      0.267   -0.021~+0.155
λ=0.3         1.1098       0.150      0.368   +0.047~+0.191
λ=1           1.1407       0.112      0.361   +0.065~+0.187
λ=3           1.1407       0.133      0.275   +0.049~+0.249
★ 무작위 바닥   1.8753      -0.007      0.000
```

### 순위 적합 — ★ 여기에 곡선이 있다

```
              regret   상위100 tau     전구간
λ=0 (기존)     1.6364       0.353      0.320
λ=0.3         1.5918       0.361      0.447
λ=1           1.5655       0.290      0.372
λ=3           1.5436       0.307      0.408
```

**regret 이 λ 에 따라 단조로 좋아진다** (1.6364 -> 1.5436, −5.7%).
tau 는 0.353 -> 0.30 근처로 내려간다.

```
λ:        0      0.3      1       3
regret  1.6364  1.5918  1.5655  1.5436     ★ 단조 감소, 기울기가 준다
tau     0.353   0.361   0.290   0.307
```

**무릎이 아니다.** regret 이 얻는 것이 전 구간 5.7% 이고, λ 를 10배
올리는 동안 계속 줄어드는 기울기다. tau 는 λ=0.3 에서 오히려 오르고
그 뒤 내려가지만 3시드 범위 안이다.

### C2. 순수 `rank_loss(k=100)` — 계열 간 비교용

아카이브의 `rank_loss` 는 λ 가 섞인 값이라 나란히 못 놓는다. 코드와
가중치에서 다시 계산했다.

```
              순수 rank_loss   학습 regret
λ=0 (기존)           0.2914       1.4683
λ=0.3               0.2826       1.6673
λ=1                 0.3326       1.5492
λ=3                 0.3275       1.3374
```

### 판정 (사전 등록 §5-2)

```
무릎이 있다   절충점이 존재한다
직선이다      ★ 교환율이 일정하다 — 벽의 다른 표현
```

**직선 쪽이다.** 그리고 그 직선의 기울기가 얕다 — λ 를 0에서 3으로
올려 regret 을 5.7% 얻는다. 벽(1.11 vs 1.64, 48%)에 비하면 작다.

## 5. 정정 이력

- **2026-09-03** 처음 돌렸을 때 §A2 의 k=10 tau 가 `nan` 이었다.
  홀드아웃 한 형상에서 **규칙이 상위 10 에 상수 점수**를 줘서
  Kendall tau 가 정의되지 않는데, `_measure` 가 그것을 그대로
  중앙값에 넣고 있었다. **두 번째로 밟은 자리다** (`top-tau.md`).
  `_measure` 가 **정의 안 되는 형상 수를 네 번째 값으로 돌려주게**
  고쳤다 — 이제 조용히 못 지나간다. 옛 `nan` 값은 여기 남긴다.
- **2026-09-03** 곱 쌍을 세면서 두 피연산자를 **합집합으로 접고**
  있었다. `f.a * f.a`(제곱)와 `f.a * f.b`(곱)가 같은 이름이 됐다.
  가장 많이 나온 것이 실제로는 제곱이었으므로 이 오류가 §B 의
  해석을 통째로 바꿨을 자리다. 양쪽을 따로 남기게 고쳤다.

## 5b. ★ 지표 셋을 나란히 (2026-09-03, D-118)

벽이 지표 하나의 인공물이 아니라는 것이 그 자체로 증거다.

```
tau (옛것)        ✗ 노이즈로 못 가르는 쌍을 채점한다 — 지표가 틀렸었다
노이즈 인식 tau   ✓ 순서 능력      (못 가르는 쌍을 동률로 묶는다)
★ regret@k       ✓ 영역 선택 능력  (평균이라 노이즈에 강하다)
```

```
                   옛 tau  노이즈 tau  regret@100   무작위 바닥
regret 구조+regret w  0.122     0.158      1.106     tau -0.007 / r@100 2.378
순위 구조+순위 w        0.353     0.410      1.536
```

★ **세 지표가 같은 방향을 가리킨다.** 노이즈 인식 tau 는 전부 오르지만
(+0.019~+0.106) 팔의 순서가 안 바뀌고, `regret@k` 는 어느 k 에서도
시드 범위가 안 겹친다.

### ★ 벽의 정확한 진술

```
순위 규칙   참 상위 100 을 주면 그 안의 순서는 매긴다   (노이즈 tau 0.410)
           그런데 자기가 상위 100 을 고르면 틀린 것을 고른다 (regret@100 1.536)
```

**국소적으로는 맞고 전역적으로는 틀리다.** 앞서 "전 구간 tau 0.50" 과
"상위권 tau 낮음" 이 갈렸던 것도 같은 얘기다.

```
regret 규칙   ★ 좋은 영역을 찾는다. 그 안의 순서는 못 매긴다
순위 규칙     ★ 순서는 매긴다. 어느 영역이 좋은지 모른다
```

자세한 것은 [regret-at-k.md](regret-at-k.md).

## 6. 셋을 합치면

```
A  k 를 좁혀도    벽이 그대로다. ★ regret 은 오히려 나빠진다
B  곱을 명시해도  벽이 그대로다. 순위 쪽만 조금 (0.353 -> 0.370)
C  λ 를 올려도    직선이다. 무릎이 없다
```

앞의 넷과 같은 곳을 가리킨다:

```
구조가 아니다     축 자카드 1.000 (feature-overlap.md)
예산이 아니다     8 vs 16 구분 불가 (D-108)
순서가 아니다     rank->regret / regret->rank 둘 다 (D-104)
표현력이 아니다   곱은 원래 됐고, 명시해도 벽은 그대로 (D-110)
목표 정의도 아니다 k 를 10~100 으로 훑어도, λ 를 0~3 으로 훑어도
```

★ 남은 후보는 하나다 — **가중치 벡터가 형상마다 하나**라는 것.
지금은 체제별로 둘이다. 셋 이상으로 나누거나, 형상에 따라 연속적으로
바뀌게 하는 것(= 가중치가 비선형 자리에 들어가는 형태)이 남았다.
그것은 새 조건이므로 **새 사전 등록이 필요하다.**
