## A. `k` 스윕 — 상위 몇 개까지 볼 것인가

### 값

```
k = 10, 20, 50      각 3시드 x 12라운드
k = 100 은 기존 (runs/f1pipe-F3-rankevo-s0..2, D-101)
```

### ★ k = 5 는 **안 돌린다** — 미리 재고 결정했다

학습 41형상에서 노이즈 바닥으로 **가를 수 있는 쌍**을 셌다 (LLM 0회):

```
   k   가능 쌍    가를 수 있는 쌍   남는 비율   형상당    상위 k 폭(중앙)
   5      410            73       17.8%     1.8      0.5%
  10    1,845           610       33.1%    14.9      1.3%
  20    7,790         3,143       40.3%    76.7      3.5%
  50   50,225        20,697       41.2%   504.8      4.1%
 100  202,950        89,928       44.3%  2193.4      6.6%
```

k=5 는 형상당 1.8쌍이다. 손실 곡면이라 부를 수 없고, 상위 5 의 폭
중앙이 0.5% 로 노이즈 바닥과 붙는다. **결과를 보고 뺀 것이 아니라
돌리기 전에 재고 뺐다.**

### 주 지표 (전부 홀드아웃)

```
★ regret 재적합 tau 와 regret 을 **함께** — 교환율이 어디서 꺾이나
순위 적합 tau (★ 그 실행의 k 기준으로 잰다)
★ 무작위 바닥 — k 마다 다르다. 매번 20뽑기
전구간 tau
```

### 판정

```
k 가 줄수록 regret 이 좋아지면서 tau 가 유지   ★ 벽이 낮아진다
k 가 줄면 tau 만 따라 내려간다                ★ 벽이 그대로다
```

⚠️ **k 는 프롬프트에도 들어간다.** 목표 정의가 "config 100개" 를 상수로
적고 있었다 (D-105/D-107 과 같은 자리, 다섯 번째 면). 고쳤고 시험으로
고정했다 (`test_objective_block_states_the_running_k`).

## B. 곱 항 — 표현력

### ★ 먼저: 정적 검사는 **원래 곱을 막지 않았다**

지시는 "정적 검사에서 그 규칙 하나를 푼다" 였는데, 확인해 보니
**그런 규칙이 없다.** `(f.a * f.b) * w[0]` 은 지금도 그대로 통과한다
(`check_rule` 위반 0 / 경고 0). 그리고 이미 쓰이고 있다:

```
전체 규칙 531개 중 f.* x f.* 곱을 쓰는 것 312개 (59%)
  b16b   33/33      rankevo  25/38      b08  18/30      arch24  23/53
예: (f.pipeline_warmup_frac + f.smem_pressure) * np.exp(-f.log_mainloop_iters)
```

### 그래서 조건은 "푸는 것" 이 아니라 "말해 주는 것" 이다

D-107 에서 배운 대로, 프롬프트·스키마에 안 실리면 시도가 안 는다.
`--product-hint` 를 네 면에 같이 싣는다:

```
시스템 프롬프트   _rules_common.md 에 "## ★ 항의 형태 — 피처를 곱해도 됩니다" + 예시
사용자 프롬프트   role/rule_editor.md 의 예산 절 아래 한 줄
출력 스키마      code 필드 설명에 한 문장
검사기          ★ 바꿀 것이 없다 — 원래 안 막았다
```

⚠️ 끄면 프롬프트가 이전과 **바이트까지 같다** (확인함). A·C 는 안 켠다.

### ★ 예상 — 효과가 작을 것이다

이미 59% 가 쓰고 있으므로 "허용" 이 새로 여는 것이 없다. 오르는 것이
있다면 **빈도와 의도**이지 가능성이 아니다. 그래도 돌리는 이유는
D-107 이 정확히 "말해 주면 달라진다" 를 보였기 때문이다.

### 설계와 판정

```
3시드 x 12라운드, k=100, 예산 8, 같은 씨앗, --product-hint

주 지표   ★ regret 재적합 tau — 곱 항이 벽을 낮추나
관찰     곱 항 빈도 (규칙당 개수) — 기준선 대비
         ★ 어떤 쌍인가, 물리적으로 말이 되는가 (안 되면 그것도 결과다)
         AST 노드 / 항 수 / 거부율
```

★ **곱 항 빈도가 기준선(59%)에서 안 오르면** "말해 줘도 안 는다" 이고,
그것은 표현력이 병목이 아니라는 증거를 하나 더 얹는다.

### 시작 전 확인 (D-107 절차)

네 면을 렌더링해 눈으로 보고, **1라운드 실측으로 곱 항이 실제로 늘었는지**
본다. 안 늘면 고치고 다시.

## C. λ 스윕 — 두 손실의 합

### ★ `regret` 을 **직접 넣지 않는다**

`regret` 은 `argmin` 을 거쳐 계단이다. 합치면 L-BFGS 를 못 쓰고
Nelder-Mead 로 돌아가야 하며 D-77 이 다시 걸린다. 그래서 **부드러운
대리**를 쓴다:

```
L(w) = rank_loss(k)  +  λ · rank_loss_top1(k)

rank_loss_top1  참 1등이 낀 쌍만 (i = 참 1등). 같은 가중치 |Δt|/t_best,
                같은 노이즈 필터, 같은 정규화(쌍 무게 합으로 나눔)
```

⚠️ **이것은 regret 이 아니다.** 1등을 맞히는 쪽에 무게를 더 얹는
것이고, `rank_loss(k)` 쌍 집합의 **부분집합**을 재가중하는 것이다.
그래서:

- 두 항의 정규화가 같아 **λ 가 순수한 비율**이다. 무작위 바닥으로
  나누는 별도 정규화가 필요 없다.
- 실험 A 와 이어진다 — "1등만 보는 것" 과 "상위 k 를 보는 것" 을
  섞는 축이다.

### 값

```
λ = 0.3, 1, 3       각 3시드 x 12라운드, k=100, 예산 8
λ = 0 은 기존 (rankevo)
```

### 주 지표

```
★ regret 과 tau 의 파레토 곡선 (홀드아웃)
   λ 를 올리면 regret 이 좋아지고 tau 가 나빠질 것이다
```

### 판정

```
무릎이 있다   ★ 절충점이 존재한다. 벽이 아니라 곡선이었다
직선이다      ★ 교환율이 일정하다 — 벽의 다른 표현
```

⚠️ **채택도 같은 목적함수로 한다** (원칙 37). 아카이브의 `rank_loss` 에
합친 값을 넣는다 — 람다를 빼고 고르면 최적화한 것과 다른 것으로 뽑는다.
계열 간 비교용 **순수 `rank_loss(k=100)`** 은 보고 때 코드·가중치에서
다시 계산한다 (D-104 에서 쓴 방법).

⚠️ λ 도 프롬프트에 싣는다 — 목표 정의가 실행 조건과 같은 말을 해야
한다.
