## 1. 먼저 — 예산이 구속했나

세 번 틀린 자리라 이것부터 본다.

```
            예산 소비 (리터럴+가중치)          항 수
예산 8      중앙  8.0 / 상한  8   28/30 이 상한   중앙  8.0 (7~8)
예산 16     중앙 16.0 / 상한 16   21/33 이 상한   중앙 13.0 (5~15)
```

**구속했다.** 항 수가 8 -> 13 으로 늘었고, 규칙의 2/3 가 예산을 끝까지
쓴다. AST 노드는 최대 543 까지 갔다 — 상한을 400 에 두었으면 거부됐을
것이다 (D-106 이 없었으면 이 실험도 무효였다).

⚠️ **정정.** 사전 등록에 "16항을 쓰는 규칙이 3시드 중 0개면 무효" 라고
썼다. **단위를 잘못 썼다** — 예산은 항이 아니라 `숫자 리터럴 + 가중치`
를 센다. 항 수로는 최대 15 지만 예산 소비로는 상한에 닿는다. 판정은
소비 단위로 한다.

## 3. 판정

```
regret 재적합 tau 중앙  >= 0.20   벽을 뚫었다
                       <= 0.10   벽은 예산 탓이 아니다
예산 16 의 값            -0.043   ★ 벽은 예산 탓이 아니다
```

**사전 등록한 예상이 맞았다.** 예상의 근거는 두 목적함수 계열의 축
자카드가 1.000 이라는 것이었다 ([feature-overlap.md](feature-overlap.md)
§5) — 담을 축이 모자란 것이 아니라 **가중치 하나가 두 순서를 동시에
못 만든다.**

곁가지 확인:

- **순위 적합에서도 이득이 없다** (0.374 -> 0.364, 범위가 겹친다).
  예산은 순위 능력 자체도 못 올린다.
- **학습에서는 조금 낫다.** 최종 순위 손실(학습, 체제별)이 8 에서
  0.2881, 16 에서 0.2705 다. **홀드아웃 tau 로는 안 넘어온다.**
- regret 은 두 팔이 같다 (1.1329 vs 1.1233, 바닥 1.8753).

⚠️ 3시드는 유의성을 못 낸다 (원칙 27). regret 재적합 tau 의 범위는
`+0.035~+0.208`(8) 과 `-0.079~+0.131`(16) 으로 **겹친다** — "16 이 더
나쁘다" 고는 말할 수 없다. 말할 수 있는 것은 "16 이 판정선 0.20 을
넘지 못했고 8 보다 나아지지도 않았다" 뿐이다.

## 4. 과적합 · 적합기 · 비용

```
            학습     홀드아웃     격차       적합기 도달  거부율  config    분
예산 8    1.6362   1.6281   -0.0854    100.0%   2.1%     7    66.9
                시드별 -0.1062 -0.0854 -0.0081
예산 16   1.5107   1.4891   -0.0657    100.0%   3.2%     7    79.8
                시드별 -0.0657 -0.0216 -0.1318
```

- **격차가 6/6 시드에서 음수다** — 홀드아웃이 학습보다 낫다. 예산을
  두 배로 줘도 과적합 징후가 안 나온다.
- **적합기 도달률 100%** — 16차원에서도 다 움직인다. D-77 의 "적합기가
  고차원에서 못 간다" 는 순위 경로에서 안 나타난다 (D-103 과 일치).
- 거부율 2~3%. 예산 16 의 거부 14건(스키마 1 / 정적 7 / 샌드박스 1 /
  적합 5) 은 전부 중단 조건(50%)과 멀다.

### 상한 측정의 다섯 축 (/3 시드)

```
              split_k_cost  sm_idle_cost  pipeline_warmup  tail_waste  waves
예산 8              3            3              3             0         3
예산 16             3            3              3             2         3
축 수                    16/15/15 (합집합 18)      17/19/19 (합집합 19)
```

예산 16 은 축을 두세 개 더 담고 `tail_waste` 를 집는다. **그래도
홀드아웃 tau 는 안 움직인다.**

## 5. 그래서 벽은 무엇인가

```
축 용량이 아니다   자카드 1.000, 예산 16 에서 축 19개까지 담아도 그대로
표현력이 아니다    항 13개, 노드 543 까지 써도 그대로
★ 남은 것         가중치 벡터 **하나**가 두 순서를 동시에 못 만든다
```

D-103 의 상호작용 · D-104 의 벽 · 여기의 예산 실험이 같은 곳을 가리킨다.
다음에 벽을 건드리려면 **가중치를 하나로 두는 것** 자체를 깨야 한다 —
체제별로 이미 둘이니, 셋 이상으로 나누거나 목적함수를 합치는 쪽
(`pending_fixes` 8) 이 남는다. 둘 다 새 조건이 생기므로 새 사전 등록이
필요하다.
