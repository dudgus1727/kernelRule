# 실험 계획서 — 4090 전이: **세 쌍 여섯 방향**

**계산 전에 쓴다.** (a)(b) 는 LLM 0회, (c) 4090 은 한 번 돈다.

## 0. 번들은 통과했다

```
NVIDIA GeForce RTX 4090 (sm_89)   env_hash ad95d455dfdd613b
1,223,195행 / 64형상 / 6,285커널   ridge 159.875
schema v3   aggregate_status='all'
noise  sigma_abs 0.00074334 / sigma_rel 0.00220603 / tick 3.2e-05
```

`bundle_guard` 통과 (D-125 — 검사기의 자릿수 결함을 고친 뒤).

## 1. ★ 겹침 — 우리 도구의 값이 예고와 다르다

`transfer_check` (형상 키 = M,N,K,dtype):

| 쌍 | 공통 형상 | 정렬 후 | 학습/홀드아웃 | 바운드 뒤집힘 | ridge 비 |
|---|---:|---:|---|---:|---|
| A6000 ↔ 4090 | **50** | 45 | 25 / **20** | **0** | 1.00배 |
| A6000 ↔ 5090 | **53** | 48 | 28 / **20** | **4** | 0.74배 |
| 4090 ↔ 5090 | **53** | 48 | 28 / **20** | **3** | 0.74배 |

⚠️ **예고값과 두 쌍이 다르다.**

```
              예고        우리 도구
A6000↔4090   공통 61 · 뒤집힘 0   ★ 50 · 0
A6000↔5090   공통 53 · 뒤집힘 4     53 · 4      ← 정확히 같다
4090 ↔5090   공통 60 · 뒤집힘 4   ★ 53 · 3
```

**A6000↔5090 이 정확히 맞으므로 도구가 고장난 것은 아니다.** 4090 표의
형상 쓸이가 **위로 옮겨졌다**:

```
A6000 에만 (16)  (1|8|32, 4096,4096)  (128,4096,{256,1024,4096,16384})
                 (512,512,512) (1024,1024,1024) (1024,4096,{128..16384})
4090 에만 (14)   (640|1152|3456, 4096,4096)  (4096,4096,{256,1024,16384})
                 (8192,4096,{128..16384})  (16384,16384,16384)
```

작은 M 쪽이 빠지고 큰 M 쪽이 들어왔다. **큰 GPU 라 쓸이를 키운 것으로
보인다** — 그러면 겹침이 주는 것이 맞다.

★ **우리 도구의 값을 쓴다.** 절차가 산출물에 적혀 있고 재현된다
(`transfer-overlap-*.json`). 예고값과의 차이는 kernelTab 에 확인을
요청할 사항이지, 우리 수치를 바꿀 근거가 아니다 (원칙 2).

★ **홀드아웃은 세 쌍 모두 20형상이다** — 차이는 전부 학습 쪽이다.
그래서 세 쌍의 수치를 나란히 놓을 수 있다.

## 2. 세 팔 — §29.5 그대로

```
(a) 완전 이식   출처 GPU 의 구조 + 가중치 그대로 -> 대상 표에서 채점
(b) 재적합      구조 고정, 대상 표의 학습 분할로 가중치만 다시
(c) 재생성      대상 표에서 처음부터
```

여섯 방향 = 세 쌍 x 두 방향. (a)(b) 는 조합이 몇 개든 **LLM 0회**다.

```
(c) 출처
  A6000   arch24 6시드           (있다)
  5090    5090sigma-hw2 3시드    (있다 — ★ 사다리의 **새 (c)**, hw 가 맞는 것)
  4090    ★ 4090sigma 3시드      (없다 -> 이번에 한 번 돈다)
```

⚠️ **세 (c) 는 같은 판이 아니다.** `arch24` 는 D-113·116·117(hw 프롬프트
생성) 이전이고 `arch_prompt='hw/sm_86.md'` 를 썼다. 5090 과 4090 은
번들에서 생성한 hw 를 받는다. **(c) 끼리 견줄 때 이 차이를 적는다**
(원칙 4). D-119 가 잰 바로는 hw 산문은 12라운드 성능을 안 바꾼다
(구분 불가) — 그러나 "안 바꾼다" 가 아니라 "못 갈랐다" 였다.

### (c) 4090 실행 — 5090 새 (c) 와 **명령이 같다**

```
python3 experiments/f1_pipeline.py F3 \
  --seed-source rule_writer --n-rule-writer 10 \
  --bundle datasets/rtx-4090-sm_89-ad95d455 --env-hash ad95d455 \
  --n-seeds 3 --rounds 12 --workers 6 --tag 4090sigma
```

적합기는 **기본값(nelder-mead/4, max_evals 200)** 이다 — D-125 의 결정.
hw 프롬프트는 번들에서 자동 생성되고 `check_hw_prompt` 가 GPU 이름과
눈금을 확인한다. 시작 전 확인했다: `tick_binds=False` (눈금 0.0005% <
통계 0.0135% @ 65.5us) 라 **"이 표에서는 눈금이 한계가 아닙니다"** 절이
간다 — 5090 과 같고 A6000 과 다르다 (D-116).

## 3. 적합기 — NM 그대로

```
(b) 재적합 · (c) 진화 · 채점 재적합   전부 nelder-mead / 재시작 4
```

D-125 가 8차원에서 NM 과 CMA 가 구분 불가임을 확인했고, **옛 전이 수치와
나란히 놓아야 하므로** 절차를 안 바꾼다 (원칙 4). 16차원은 이 실험에
안 나온다 (예산 8).

## 4. 판정선 — **규칙을 박고, 숫자는 재서 채운다**

```
σ   A6000 0.0124   5090 0.0130   ★ 4090 = (c) 3시드에서 잰다
    n=3 의 σ 는 넓다 -> 카이제곱 95% 상한을 함께 낸다 (sigma_5090.py 그대로)
delta   두 팔 n=3, 양측 0.05, 검정력 0.8, 비대응
        ★ delta = max(0.0516, 그 쌍의 σ 상한으로 계산한 값)
        -> 4090 σ 가 더 넓으면 **더 큰 선**을 쓴다. 결과를 보고 고르지 않는다
```

★ 그리고 **그 팔의 실제 시드 폭을 함께 보고한다** (원칙 7 의 새 절,
D-125) — "구분 불가" 가 "차이가 없다" 로 읽히지 않도록.

## 5. ★ 무엇을 묻나 — 세 쌍이라야 물을 수 있는 것

```
질문 1   A6000↔4090 에서 (a) 가 되나
         ★ 바운드 뒤집힘이 **0** 인 쌍이다. 여기서도 (a) 가 안 되면
           원인은 "체제가 뒤집혀서" 가 아니라 **규모(SM 84->128,
           대역폭 1.35배)** 다
질문 2   그 쌍에서 (b) ≈ (c) 가 유지되나
         5090 에서 그랬다 (§29.5). 뒤집힘 0 인 쌍에서도 그러면
         "구조는 옮겨지고 가중치는 하드웨어 상수" 가 두 쌍에서 선다
질문 3   ★ 세 쌍에서 (a) 의 나쁨이 **ridge 차이와 상관**이 있나
         ridge 비  A6000↔4090 1.00  /  나머지 둘 0.74
         (a) 손해   ?
         ★ 쌍이 셋뿐이라 **기술 통계다.** 상관계수를 내지 않는다 —
           "같은 방향인가" 까지만 말한다 (원칙 27)
```

## 6. 미리 적는 해석

```
질문 1 이 '된다'   ★ 뒤집힘이 전이의 조건이다. 체제가 유지되면 이식된다
질문 1 이 '안 된다' ★ 규모만 달라도 안 옮겨진다 -> 가중치는 하드웨어 상수
                   (§29.5 의 결론이 더 강해진다)
질문 3 이 '상관 있다' ridge 가 전이 난이도의 축이다 (쌍 3개짜리 관측)
질문 3 이 '없다'    남는 축은 규모다
```
