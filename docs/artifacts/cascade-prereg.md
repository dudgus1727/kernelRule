# 실험 계획서 — Cascade: 벽을 **배포 시점에** 우회할 수 있나

**LLM 0회.** 계산 전에 쓴다. 근거: [D-118](../decisions.md),
[regret-at-k.md](regret-at-k.md).

## 1. 왜 — 벽의 두 진술이 **상보적**이다

```
regret 규칙   좋은 영역을 찾는다   ★ 그 안의 순서는 못 매긴다
순위 규칙     순서는 매긴다        ★ 어느 영역이 좋은지 모른다
```

그러면 이어 붙이는 것이 자연스럽다.

```
1단계   regret 규칙으로 상위 k 를 추린다      (영역 선택)
2단계   순위 규칙으로 그 안에서 1등을 고른다   (순서)
★ 둘 다 µs. 규칙이 둘이 될 뿐이다
```

**이것은 벽을 없애는 것이 아니라 배포 시점에 **우회**하는 것이다.**

## 2. 조건

```
1단계   regret 팔 6구조 (arch24-s0..5, regret 가중치)
2단계   순위 팔 3구조   (rankevo-s0..2, 순위 가중치)
★ 18 조합 전부. "짝" 이 임의이므로 하나를 고르지 않고 **분포로 낸다**
k = 10, 20, 50
가중치는 둘 다 체제별로 학습 분할에서 재적합 (최종 채점 §10)
A6000 홀드아웃 20형상 · 기하평균
```

## 3. 낼 것 넷

```
★ cascade regret@1          18조합 x 3k
   기준선  regret 단독 regret@1   중앙 1.076, 시드 범위 1.0566~1.0919
★ 천장    oracle@k — 1단계의 상위 k 안 **최선**을 고른다면
          (2단계가 완벽할 때의 값. hit@k 도 함께)
★ 바닥    1단계의 상위 k 안에서 **무작위**로 고른다 (20뽑기)
          2단계가 아무것도 안 더할 때의 값
   무작위 바닥 (전체에서 무작위) — 원칙 7
```

★ **천장과 바닥 사이 어디인가**가 "2단계가 얼마나 일하나" 다.

## 4. 판정선

```
cascade 중앙이 regret 단독 시드 범위 **아래**(< 1.0566)
  ★ 우회된다. 갈래 2 에 "배포 시점 우회 가능" 이 붙는다
범위 **안**(1.0566~1.0919)
  ★ 안 된다. 순위 규칙이 좋은 영역 안에서도 못 고른다
범위 **위**(> 1.0919)
  ★ 2단계가 해를 끼친다
```

보조:

```
cascade 가 **바닥(무작위 in top-k)** 과 구분 불가
  -> 2단계가 아무것도 안 더한다. 순위 규칙의 순서 능력이 상위 k 에서는 없다
cascade 가 **천장(oracle@k)** 에 가깝다
  -> 2단계가 거의 완벽하다. 남은 손실은 1단계의 hit@k 다
```

## 5. ⚠️ 미리 적는 유보

```
두 규칙이 다른 시드 계열이라 **짝이 임의**다 — 전 조합의 분포로 읽는다
18 조합은 독립 표본이 아니다 (구조 9개에서 나온다). 유의성을 안 낸다
k 는 실험 계획서에 박은 셋뿐이다. 결과를 보고 다른 k 를 고르지 않는다
```

## 6. ★ 예상

**범위 안일 것으로 본다 (= 우회 안 된다).** D-118 에서 순위 규칙의
`regret@k` 가 어느 k 에서도 regret 규칙보다 나빴다 — 상위 100 안에서도
그랬다. 상위 10~50 으로 좁혀도 순서 능력이 갑자기 생길 이유가 없다.

다만 **바닥과의 거리**는 볼 만하다. 2단계가 무작위보다 나으면 "순서
능력이 있긴 하다" 는 것이 `regret@k` 와 독립적인 확인이 된다.

## 7. 비용

LLM 0회. 적합 9회(구조 9개 x 체제 2) + 평가. 약 10분.
