## D-99 와 무엇이 다른가 — **같은 질문의 반복이 아니다**

```
D-99 설계   양성 상위 32  vs  음성 순위 구간별 256
            ★ 쉬운 쌍(상위32 대 1만등)이 개수로 지배했다
            최종 쌍 손실 0.02~0.24 — 순서는 거의 완벽한데 regret 은 6/6 나빴다

이번 설계   ★ 참 상위 100 안에서만 쌍을 만든다 — 쉬운 쌍이 아예 없다
            ★ 가중치를 |Δt|/t_best 로 — 상위일수록 실제 손해에 비례
            ★ 그리고 fit_weights 자체를 바꿔 **진화 루프 안에서** 돈다
              (D-99 는 실험 스크립트에서 가중치만 다시 맞춘 것)
```

## 2. 손실 — 튜닝할 값이 없다

```
쌍       각 형상의 참 상위 K=100 안의 모든 (i, j), t_i < t_j
제외     ★ 노이즈 바닥으로 못 가르는 쌍 (`NoiseModel.resolvable`, 정본)
가중치   ★ w(i,j) = (t_j - t_i) / t_best      실제 손해에 비례한다
         노이즈 바닥 이내면 자동으로 0 에 가까워진다
손실     L = Σ w(i,j) · softplus(s_i - s_j) / Σ w(i,j)
온도     ★ T = 1 **고정**. s = Φw 라 T 는 w 크기와 분리 식별되지 않는다
         (D-99 에서 확인). 선택이 아니라 정규화다
```

**하이퍼파라미터가 하나도 없다.** `K` 만 정하면 되고 아래에서 박는다.

### K = 100 의 근거

```
A6000 상위 100  시간 폭 6.6%, 고유 시간값 24 — 배울 순위가 있다
⚠️ 다만 고유값 10개 이하인 형상이 10/41 이다
```

**★ 정하고 나면 안 바꾼다.** 결과를 보고 `K` 를 조정하면 "맞을 때까지" 다.
형상별 가변 `K` 도 안 쓴다 — 그것을 쓰려면 지금 박아야 하는데 안 박는다.

## ★ 정정 — 배관 확인에서 **설계 모순**을 찾았다 (2026-09-01, 같은 날)

**아래 §3 의 원안은 "채택은 regret, 학습은 rank" 였다. 그것이 모순이다.**

```
학습   순위 손실로 가중치를 맞춘다
선택   ★ regret 으로 채택한다
-> 진화가 "순위를 잘 매기는 구조" 가 아니라
   ★ "rank 로 맞춰도 안 터지는 구조" 를 고르게 된다
-> 재는 것이 "순위 손실로 진화하면 무엇이 나오나" 가 아니라 D-99 의 확장이다
```

**★ 아카이브 채택 판정을 `rank loss` 로 바꾼다.**

```
바꾼다   같은 셀 안에서 더 나은가의 기준   regret -> rank loss
★ 안 바꾼다  셀 축 자체 (코드 길이 / 짧은 regret / 긴 regret)
           축은 **다양성을 만드는 장치**이고 채택이 목표를 정한다.
           축까지 바꾸면 변수가 둘이 된다
★ 안 바꾼다  판정선 (tau >= 0.30 / <= 0.15)
★ 안 바꾼다  regret 은 계속 계산해서 기록한다
```

### 이것이 "결과 보고 고치는 것" 인가 — 아니다

```
판정선          안 바꾼다
설계의 자기모순   ★ 고친다
관측된 수치      tau 0.158~0.352 — 이걸 보고 판정선을 바꾸는 것이 아니다
```

**이 모순은 숫자 없이도 찾을 수 있었다.** 배관 확인이 그것을 잡은 것이
그 단계의 목적이다.

### "기존 결과와 나란히 못 놓는다" 는 걱정이 과했다

```
못 놓는 것   "이 실행의 아카이브 최고" 끼리 — ★ 최고의 정의가 다르다
놓을 수 있는 것
  ★ 최종 규칙을 홀드아웃에서 regret 으로 채점
  ★ 최종 규칙의 상위100 tau / 전구간 tau
  둘 다 **사후에 같은 홀드아웃에서** 계산한다
```

**선택 기준이 달라도 산출물은 비교된다.**

## ★ 정정 (2) — 본 실행 전, 설계 정합성 셋 (2026-09-01)

**★ 판정선(tau >= 0.30 / <= 0.15)은 안 바꾼다.** 아래 셋은 "결과를 보고
고치는 것" 이 아니라 **채택은 순위 손실인데 칸은 regret 으로 갈리던**
상태를 맞추는 것이다.

### (1) `fit_weights` 기본값을 `"rank"` 로

```
처음    기본 "regret".  이유는 "기존 결과가 통과한 경로다"
★ 지금  기본 "rank".    ★ 지금 하는 실험이 순위 손실이다
        옛 조건은 `objective="regret"` 을 명시하면 된다 — 그 재현이
        드물지 이 실험이 매번이다
```

반대 방향 대조를 시험으로 고정했다
(`test_explicit_regret_still_reproduces_the_old_path`).

### (2) ★ 셀 축을 목적함수로 통일 — 절대 경계 대신 **순위 4분위**

```
전    short_regret / long_regret 에 절대 경계 [1.0, 1.05, 1.15, 1.35, inf]
      ★ regret 규모에 맞춘 값이다. 순위 손실은 0.43~0.47 이라
        **전부 첫 칸에 몰린다**
후    ★ 보유 엘리트 + 새 후보를 목적함수로 정렬해 4분위
      경계값이 필요 없고 목적함수가 무엇이든 그대로 돈다
이름  short_regret -> short_objective,  long_regret -> long_objective
```

**기준은 (b) 아카이브 전체 + 새 제안**이다. 그 라운드의 12개 안에서만
매기면 옛 아카이브와 비교가 안 된다. 아카이브가 최대 64개라 정렬이
공짜다.

⚠️ **대가를 안다.** 칸의 뜻이 라운드마다 바뀐다 — 전체가 좋아지면
1분위의 절대값이 내려간다. 그 대신 칸이 고르게 찬다. 지금은 절대
경계라 셀 점유가 9~15/64 에 머물고 진화가 좋은 칸으로 몰린다.

### (3) `regret` 은 계속 기록한다

계산이 공짜이고 `conclusion.md` 에서 두 진화를 나란히 놓을 때 쓴다.
**판정에는 안 쓴다.**

## 4. ★ 주 지표는 regret 이 아니다

```
★ 상위 100 tau     regret 진화: 0.141 (분해능 통제 후 0.096)
★ 전 구간 tau      regret 진화: 0.30~0.56
★ 어떤 항이 살아남나  쓴 피처 집합의 자카드 / 항 수 / 분기 유무

보조   regret (★ 나빠질 것을 알고 재는 것)
      config 다양성 (regret 진화 중앙 14.5종)
```

### 판정선 — 미리 박는다

```
상위 100 tau (6구조 중앙, 통제 없음)
  >= 0.30   ★ 성공. "순서를 매기는 규칙" 이 나온다
  <= 0.15   ★ 실패. 다만 **원인을 단정하지 않는다** — 셋이 섞여 있다
            1 피처가 그 축을 못 잰다   ★ 상한 측정이 이쪽을 지지한다
              (상위 100 에서 타일이 2종뿐이고, 상수인 피처 4개가
               전부 타일·스필 계열이다 — ranking-ceiling.md §3)
            2 손실 설계가 여전히 나쁘다
            3 상위 100 안의 신호가 원래 약하다 (5090 은 폭이 1.2%)
            **"피처 한계일 가능성이 높다" 까지만 쓴다**
  그 사이    구분 불가

전 구간 tau
  >= 0.30 유지   두 능력이 양립한다
  <= 0.15        ★ 상위권을 얻고 굵은 순위를 잃었다 — trade-off 다

regret   ★ 판정에 쓰지 않는다. 기록만 한다
```

### ★ regret 이 얼마나 나빠질지 미리 적는다

```
D-99 (가중치만 다시 맞춤)   +0.0269   6/6 나빴다
이번 (진화 전체)            ★ **더 나빠질 것으로 본다**
```

근거: 목적함수가 가중치뿐 아니라 **구조 선택까지** 바꾼다. 아카이브
채택·부모 선택·조기 종료가 전부 순위 손실로 걸러지므로, regret 기준
으로는 D-99 보다 더 멀어지는 것이 자연스럽다.

⚠️ **그러나 이것은 판정이 아니다.** 예상보다 덜 나쁘면 그것도
관찰이고, 더 나빠도 실패가 아니다 — 물어야 할 것은 tau 다.

⚠️ **3시드는 유의성을 못 낸다.** 범위 분리와 시드 폭(σ = 0.0124)으로
읽는다 (D-89 와 같은 처리).

⚠️ 판정선은 §1 상한을 **보기 전에 정한 값이 아니다** — 상한을 먼저
쟀다. 그러나 **상한을 보고 무르게 하지 않았다**: 0.30 은
`degeneracy-prereg.md` 에 박아 둔 것과 같은 값이다.
