**LLM 호출 전에 쓴다.**

## 0. 왜 정본부터인가

D-128 이 프롬프트 문구를 바꿨다 (`예산` -> `파라미터`). 그리고 그 앞으로도
프롬프트가 여러 번 바뀌었다 (hw 자동 생성 D-113·116·117, 가설 필드 허용
목록 D-117, 리터럴 규칙 D-78).

```
arch24 (정본 1.0762)   ★ 옛 프롬프트 · 라운드 12 · patience 10 · NM 200
앞으로의 모든 재측정      새 프롬프트 · 라운드 24 · patience 3 · NM 200
-> 나란히 못 놓는다 (원칙 4)
```

**D-124 가 이미 봤다** — 같은 씨앗·같은 피처인데 캠페인이 다르면 0.0225
차이가 났고, D-125 가 그것이 적합기 탓이 **아님**을 확인했다. 남은 후보가
프롬프트 변화들이다. **정본을 다시 재면 그 자체가 그 질문의 답이다.**

```

            (씨앗까지 다시 뽑으면 무엇이 바뀐 것인지 못 가른다)
모델        gpt-5.6-luna
프롬프트    ★ 지금 판 (D-128 포함)
```

### ⚠️ 라운드와 patience 를 **동시에** 바꾼다

```
라운드 12 -> 24     상한을 늘린다
patience 10 -> 3    실제로 멈추게 한다
★ 두 변수의 효과를 **분리하지 않는다**
```

목적이 "가르기" 가 아니라 **"수렴까지 돌리기"** 이므로 그대로 간다.
이것은 실험이 아니라 **조건 변경**이다 — 그 사실을 여기 적는다.

## 3. 판정선 — 미리 박는다

```
비교 대상   옛 정본 1.0762 (Nelder-Mead 200/600, 라운드 12, 옛 프롬프트)
기준        ★ A6000 σ 의 95% 상한 **0.0305** 로 읽는다
            (σ = 0.0124, 신뢰구간 [0.0078, 0.0305] — `transfer-29-5.md`)

|새 - 1.0762| < 0.0305    ★ 구분 불가 — 조건 변경들이 성능에 안 닿았다
|새 - 1.0762| >= 0.0305   ★ 옛 결과 전부가 다른 조건 위에 있었다는 것
★ 어느 쪽이든 **새 값을 정본으로 삼는다** — 조건 통일이 우선이다
```

⚠️ **새 값이 나빠도 옛 정본으로 되돌아가지 않는다.** 되돌아가면 앞으로의
모든 비교가 다시 갈린다.
