`design.md` §9.2 가 **"표 15시간 → 표본 5% + 수 초"** 라고 썼다.
`transfer_29_5.py` 의 (b) 는 학습 41형상 **전부**로 재적합했으므로

## 1. 곡선 — 5% 는 안 된다

5090 학습 41형상(long 11 / short 30)에서 k개를 체제별 층화로 뽑아
그것만으로 가중치를 맞추고, **홀드아웃 20형상 전부**에서 채점한다.
구조 6개 x 뽑기 10번 = k마다 60건.

```
   k    표본%     중앙      최악       폭    41 대비 중앙손실
   2    4.9%   1.1098   2.2139   1.1658      +0.0559
   4    9.8%   1.0815   2.3488   1.3034      +0.0276
   8   19.5%   1.0740   1.8788   0.8434      +0.0201
  10   24.4%   1.0748   1.3553   0.3156      +0.0209
  12   29.3%   1.0670   1.1324   0.0938      +0.0131
  14   34.1%   1.0598   1.1548   0.1128      +0.0060
  16   39.0%   1.0656   1.1531   0.1179      +0.0117
  20   48.8%   1.0652   1.1442   0.1041      +0.0113
  41  100.0%   1.0539   1.0804   0.0363       기준
```

**중앙값만 보면 k=4 (9.8%) 도 +0.0276 이라 쓸 만해 보인다.** 무너지는
것은 꼬리다 — 그 조건에서 **8번에 1번이 1.15 를 넘고 최악이 2.35** 다
(원칙 33).

```
파국 비율 (홀드아웃 > 1.15)
  k=2  30%    k=4  13%    k=8  5%    k=10  5%    k=12  0%
```

## 2. ★ 파국의 정체 — 과적합이다. 범인은 **못 가렸다**

### 2-1. 과적합이다 (적합 실패가 아니다)

```
k     파국 적합→홀드   격차   |  나머지 적합→홀드   격차
2    1.0094→1.1885   0.1792  |  1.0083→1.0876   0.0793
4    1.0252→1.2341   0.2090  |  1.0189→1.0746   0.0558
8    1.0394→1.1800   0.1405  |  1.0271→1.0708   0.0437
```

**모든 k 에서 파국의 격차가 2~4배다.** 파국 34건의 적합 regret 은 중앙
1.0145 (최소 1.0000) — **자기 표본에서는 거의 완벽하다.** 적합기가
움직인 비율도 파국 97% / 나머지 98% 로 같다.

**→ 적합 예산을 늘려도 소용없다. 정보 부족이다.**

⚠️ **정정** 처음에는 `fit_regret` 을 통째로 견줘 "파국 쪽이 더 잘
맞는다 (p = 0.0296)" 를 근거로 썼다. **k 로 층화하면 방향이
뒤집힌다** — 심슨의 역설이었다 (원칙 35). 결론은 같지만 근거가
틀렸었고, 옳은 지표는 수준이 아니라 격차다.

### 2-2. 파국이 **한 구조에 몰려 있다** — 원인은 못 가렸다

```
구조   극(분모에 피처)  floor  isfinite   파국률
s0            3          1        9      18.5%  (15/81)
s4            1          0        0       7.4%
s1,s2,s3,s5   0          0        0   2.5 ~ 4.9%
```

**여섯 구조 전부 항이 8개다 — 항 수가 원인이 아니다.**

### ⛔ 정정 — 처음 쓴 "극 때문이다" 는 성립하지 않는다

처음 여기 **"극 있음 13.0% 대 없음 4.0%, Fisher p = 0.0005"** 라고
썼다. **두 군데가 틀렸다.**

**(1) 표본 단위** (원칙 28). 그 p 는 486 **뽑기**를 독립 표본으로
셌는데 뽑기는 **6개 구조에 군집**돼 있다. 구조 수준 주장의 단위는
구조다.

```
구조 단위   극 2개 (18.5, 7.4) 대 극 없음 4개 (2.5, 3.7, 4.9, 4.9)
MWU 단측    p = 0.050
★ n=2 대 4 의 최소 가능 p = 1/15 = 0.067 (단측) / 0.133 (양측)
  어떤 효과 크기여도 유의가 안 나온다 — 검정력이 0에 가깝다
```

**(2) 기전이 실측과 어긋난다.** "분모가 0에 가까워져 폭주한다" 고
썼는데, 5090 표에서 항별 동적 범위(최대/중앙)를 재 보니 **s0 이 가장
좁다.**

```
구조     극   파국%   항별 동적범위 최댓값   최대 |항값|
s0        3   18.5           20.0            166
s4        1    7.4         1032.3             38
s1,2,3,5  0  2.5~4.9         324.0          33~320
```

폭주가 파국을 만든다면 s0 이 가장 넓어야 하는데 가장 좁다.
**극 → 폭주 → 파국은 이 자료로 지지되지 않는다.**

남는 것은 **관찰 하나**다: s0 의 파국률이 높고, s0 은 극 3 ·
`floor` 1 · `isfinite` 우회 9 로 **여러 가지가 동시에** 다르다.
구조 6개로는 어느 것 탓인지 못 가른다.

★ 원칙 28 을 우리가 쓰고 우리가 다시 밟았다. 뽑기 수가 486 이라 p 가
작게 나왔고, **작은 p 를 보고 검토를 멈췄다.**

### 2-3. ★ 오늘의 정적 검사가 s0 을 이미 거부한다

```
s0   D-92 항등 변환 검사 -> ★ 거부
s4   통과 (극이 mild: np.maximum(f.waves, f.log_grid_tiles))
```

⚠️ 이것은 **사실이지 근거가 아니다.** s0 이 거부되는 이유는
`isfinite` 우회이고, 그것이 파국의 원인이라는 증거는 위에서 무너졌다.
**"D-92 가 수치 안정성도 산다" 는 아직 근거가 없다** — 기전 하나를
반증했을 뿐이다. D-92 에도 그렇게 적었다.

**오늘의 파이프라인이 낼 수 있는 구조만 (s0 제외, 5구조):**

```
   k    표본%     중앙      최악      파국
   2    4.9%   1.0978   1.3470   12/50
   4    9.8%   1.0744   1.3643    3/50
   8   19.5%   1.0678   1.8788    2/50
  10   24.4%   1.0728   1.3553    2/50
  12   29.3%   1.0635   1.1211    0/50
```

**파국이 0이 되는 지점은 여전히 k=12 (29%)** 다.

## 3. 설계된 부분집합 — ★ 낫다는 증거가 없다

사전 등록: "무작위 뽑기는 최악의 경우를 잰다. 실무에서는 어느 형상을
잴지 우리가 고른다." 전략 넷을 **표를 재기 전에 계산되는 값만으로**
짰다 (SOL / arith_intensity / ridge 대비 위치 / 층 라벨).

```
   k       전략      중앙      최악     파국   Fisher p   MWU p
   2      layer   1.1695   1.3107   4/6      0.090    0.024  ← 설계가 나쁨
   4        sol   1.0776   1.1192   0/6      1.000    0.585
   4  sol+ridge   1.6506   3.1125   3/6      0.053    0.157  ← 설계가 나쁨
   8   전 전략    1.07~1.10  ~1.13   0/6      1.000    0.26~0.92
  10        sol   1.0508   1.0837   0/6      1.000    0.093
  12  sol+ridge   1.0911   1.1310   0/6      1.000    0.037  ← 설계가 나쁨
```

**유의에 가까운 셋이 전부 설계가 나쁜 쪽이다.** 유일하게 유망한 것이
`sol` (k=10 에서 중앙 1.0508, p = 0.093) 인데 20셀 x 2지표를 봤으니
다중비교로 죽는다.

### ★ 판정은 "설계가 나쁘다" 가 아니라 "못 가른다"

```
설계 팔은 k 마다 6건 (구조 6 x 뽑기 1 — 결정론이라 뽑기 운이 없다)
무작위 파국률 13% 에서 6건이면 기대 파국 0.8건
★ 0/6 은 아무것도 안 말한다 (95% 상한 39%)
```

사전 등록의 분기로는 **"형상 수 자체가 부족하다"** 쪽이다. 가설이
틀렸을 가능성이 높다 — 무작위가 최악을 재는 것이 아니라 **크기가
모자란** 것이었다.

**시도했고 증거가 없었다는 것을 남긴다** — 다음에 또 시도하지 않도록.

### ⚠️ `layer` 가 처음엔 조용히 안 돌았다

첫 실행에서 층 라벨이 41형상 **전부** 안 붙었다 (`{'?': 41}`).
`p.key` 는 `(M,N,K,dtype)` 인데 번들의 `shape_layers` 는 `[M,N,K]` 라
조인이 하나도 안 맞았다. **숫자는 그럴듯했다** (k=8 에서 0/6, 중앙
1.0706) — 분포를 찍어 둔 덕에 보였다. 고치고 나니 `layer` 는 **가장
나쁜 전략**이었다. 방향이 정반대였다.

사전 등록의 층 분포 예측도 틀렸다 (홀드아웃 제외 전 수를 적었다).
실제는 `a_workload 15 / b_kvary 10 / c_waves 12 / e_square 4`.

## 4. ★ "형상/파라미터 비" 는 이 자료로 못 잰다

```
   k   체제당 형상(최소)  가중치   비율   파국
   2         1            8     0.12   30%
   4         2            8     0.25   13%
   8         4            8     0.50    5%
  12         6            8     0.75    0%
  20        10            8     1.25    0%
```

비율이 0.75 에서 접히는 것처럼 보인다. **그러나 여섯 구조가 전부
가중치 8개라 "비율" 열은 `k` 의 재라벨일 뿐이다.** 가르려면 가중치
수가 다른 구조가 필요하고, 그것은 예산 8 vs 16 실험과 묶여 있다 —
그 앞은 D-77(적합기가 16차원에서 버티지 못한다)이 막고 있다.

```

잰 값           ★ 15시간 -> 약 4.5시간 (29%) + 수 초
조건            ★ 무작위 층화 뽑기
                ★ s0 계열(오늘의 정적 검사가 거부하는 구조)을 뺀 기준
                  — "극 없는" 이 아니다. 무엇이 s0 를 나쁘게 했는지는
                  못 가렸다 (§2-2)
                ★ 설계 뽑기로는 안 내려간다 (증거 없음, §3)
```

`design.md` §9.2 와 §29.5 를 그렇게 고쳤다. **옛 문장은 지우지 않고
위에 측정값을 붙였다.**
