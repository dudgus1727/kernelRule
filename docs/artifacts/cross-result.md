## ★ 정정 — 사전 등록의 시간 추정이 틀렸다

사전 등록에 **"병렬화 뒤라 약 1시간 (전에는 5시간)"** 이라고 썼다.
**실제 3시간 20분이 걸렸다.**

D-95 의 4.0배는 **채점·적합**을 잰 것인데 그것을 실행 전체에 그대로
곱했다. 실행 중 워커 CPU 는 3% 였다 — 병목은 API 지연이다. 라운드
시간이 117초에서 1013초까지 8.7배로 흔들린 것이 같은 이야기다.

**틀린 값을 지우지 않는다.** 앞으로 벽시계를 추정할 때 부분 속도 향상을
전체에 곱하지 않는다.

## 1 ★ 자식이 두 부모의 항을 실제로 섞는가 — **섞는다**

```
                        제안   섞을 수 있었던 것   섞음        통째로 베낌
f1pipe-F3-cross1-s0      33          29          21 = 72.4%       3
f1pipe-F3-cross1-s1      33          16          11 = 68.8%       3
f1pipe-F3-cross1-s2      33          29          19 = 65.5%       2
합계                     99          74          51 = 68.9%       8
```

**기준 >= 40% 를 넘었다.** 세 시드가 65.5~72.4% 로 모여 있다.

*섞음* = 자식이 **부모 A 에만 있던 피처**와 **부모 B 에만 있던 피처**를
둘 다 쓴 것. *섞을 수 있었던 것* = 양쪽 고유 항이 둘 다 존재한 제안
(99 중 74). 나머지 25건은 두 부모의 축이 겹쳐서 섞을 것이 없었다 —
분모에서 뺐다.

예산 지시도 듣는다: 합쳤을 때 **버린 항 수 중앙 1.0** (범위 -3~7).

★ 배관 확인 때 MockLLM 은 6건 전부 `mixed=False` 였다 (부모를 그대로
베낀다). 이 68.9% 는 **모델이 만든 것이지 계측 장치가 만든 것이 아니다.**

## 2 아카이브 셀 점유 — **안 늘었다**

```
cross1     6  10   6      중앙 6
abl-B     11   5   7      중앙 7
```

3 대 3 이고 두 무리의 범위가 겹친다. **차이를 말할 표본이 아니다**
(원칙 27·28). 늘었다고도 줄었다고도 못 한다.

## 3 ★ 앙상블 — **여전히 안 통한다. 그리고 이번엔 대안이 배제된다**

상위 k개의 **동률 보존** 순위 평균 (D-41), 체제별 재적합, 구조 홀드아웃.

```
                     k=1(단일)    k=3       k=5
cross1  s0            1.1163    1.1569    1.2461
        s1            1.0929    1.1154    1.1263
        s2            1.0991    1.1473    1.1212
        중앙           1.0991    1.1473    1.1263
        폭             0.0234    0.0415    0.1249

abl-B   s0            1.0687    1.0710    1.1194
        s1            1.0741    1.1286    1.1776
        s2            1.0620    1.0954    1.1025
        중앙           1.0687    1.0954    1.1194
        폭             0.0120    0.0576    0.0750
```

**6실행 전부에서 k=3 이 k=1 보다 나빴다** (부호검정 양측 p = 0.031).
폭도 두 무리 모두 k 가 커질수록 넓어진다. 앙상블이 분산을 줄이는 것은
잘 알려진 성질인데 **반대로 간다.**

★ **이것이 "결합 경로 부재" 가설을 배제한다.** `cross1` 안에서 결합
경로는 실제로 돌았고(68.9%) **같은 실행에서** 앙상블이 여전히 실패했다.
대조군이 없어도 성립하는 실행 내부 관찰이다 — D-94 교락과 무관하다.

왜 그런지도 보인다. 아카이브 **상위 5개 규칙의 피처집합 Jaccard**:

```
cross1  s0 중앙 0.75 (0.69~0.93)   s1 0.85 (0.83~0.92)   s2 0.71 (0.53~0.77)
abl-B   s0 중앙 0.92 (0.58~1.00)   s1 0.75 (0.56~0.87)   s2 0.60 (0.47~0.92)
```

상위 규칙들이 **같은 축의 60~92% 를 공유한다.** 두 무리가 구별되지
않는다. `cross` 가 제안 수준에서 섞어도 **아카이브 상위에 남는 것들은
여전히 같은 축을 본다** — 셀 축(코드 길이 / 체제별 regret)이 축의
다양성을 못 가른다는 D-42 의 원래 해석과 같은 방향이다.

## 4 부모 종류별 중복률 — **차이 없다**

```
             exploit          explore          cross
s0        7/75 =  9%       3/36 =  8%      4/33 = 12%
s1        9/75 = 12%       5/36 = 14%      4/33 = 12%
s2       11/75 = 15%       3/36 =  8%      4/33 = 12%
```

두 부모를 주면 중복이 줄 것이라 예상했는데 **`cross` 가 12/12/12% 로
가장 안정적일 뿐 낮지 않다.** 대조군은 `by_parent_kind` 를 안 남긴
시절(D-94 이전)이라 새 실행끼리만 본 것이고, 사전 등록대로다.

## 성능 — ★ 부차 지표. 판정에 쓰지 않는다

```
구조 홀드아웃 k=1   cross1  1.1163 / 1.0929 / 1.0991   중앙 1.0991
                   abl-B   1.0687 / 1.0741 / 1.0620   중앙 1.0687
```

**이 차이를 조건 탓으로 읽지 마라.** 사전 등록이 미리 적어 둔 대로
`abl-B` 는 **라운드로빈 가설 배정**이고 `cross1` 은 무작위 배정이다
(D-94). 조건이 둘 다르므로 어느 쪽 탓인지 못 가른다. 3 대 3 이고
`cross1` 자체 폭이 0.0234 라 차이 0.030 은 한 폭 남짓이다.

## 판정 — 사전 등록에 적어 둔 대로

| 미리 적은 것 | 결과 |
|---|---|
| 1 이 40% 이상 → 교차가 실제로 돈다 | ✅ 68.9% |
| 1 이 10% 이하 → 멈춘다 | 해당 없음 |
| 3 에서 앙상블 개선 → 원인은 "결합 경로 부재" | ❌ 개선 없음 |
| 3 이 그대로 → **D-42 의 원래 해석이 산다** | ✅ 이쪽 |

## 남은 것

`cross` 는 이제 진짜로 돈다. 그러나 **그것으로 앙상블이 살아나지
않았다.** 다음 후보는 사전 등록이 아니라 D-42 가 원래 가리키던 곳이다 —
**§13 의 셀 축**. 상위 규칙들이 축의 60~92% 를 공유하는데 셀은 코드
길이와 체제별 regret 으로 나뉜다. 축 자체를 다시 봐야 한다
([pending_fixes.md](../pending_fixes.md) 4번).

⚠️ 이 실행을 보고 프롬프트를 고쳐 다시 돌리지 않는다 (§12.3d).
