# 두 목적함수가 쓰는 축 — 벽이 예산 탓인가

LLM 0회. 예산 재실행 **전에** 재서 예상을 근거 위에 세운다.

```
python3 experiments/feature_overlap.py     # -> docs/artifacts/feature-overlap.json
```

대상은 `regret` 진화 6실행(`f1pipe-F3-arch24-s0..5`)과 순위 손실 진화
3실행(`f1pipe-F3-rankevo-s0..2`)의 **최종 최고 규칙 하나씩**. 두 계열은
D-102·D-103 의 2x2 가 쓴 것과 같다.

---

## 1. 두 계열은 **같은 축을 쓴다**

```
regret 합집합  19개
순위   합집합  19개
★ 자카드 1.000 — 한쪽에만 있는 축이 하나도 없다
```

레지스트리 24개 중 `arith_intensity` 하나만 아무 규칙도 안 썼다. 나머지
넷(`can_use_cp_async` `is_memory_bound` `log_sol_ms` `roofline_ratio`)은
피처가 아니라 **술어**(`p.*`)로 쓰였다.

## 2. 규칙 쌍으로 봐도 계열 사이가 계열 안보다 안 멀다

★ 자카드는 바닥이 있어야 읽힌다 (원칙 7).

```
                 n     자카드 중앙 (범위)         축 합집합 중앙 (범위)
regret 안       15    0.647 (0.444~0.938)      17.0 (15~18)
순위 안          3    0.684 (0.632~0.941)      19.0 (17~19)
★ 계열 사이      18    0.697 (0.579~0.938)      17.5 (16~19)
★ 무작위 바닥  2000    0.455                    20.7
```

**계열 사이(0.697)가 계열 안(0.647 / 0.684)보다 오히려 높다.** 세 값이
전부 바닥(0.455) 위에 있지만 서로는 구분되지 않는다.

    두 목적함수는 **어떤 물리를 지목하는지로 달라지지 않는다.**
    D-103 이 가중치를 지목한 것과 같은 방향이다.

## 3. 판정선 — 그리고 그 선이 부정확했다

지시의 선은 `합집합 <= 8` 이었다. 계열 사이 합집합 중앙은 **17.5** 고
18쌍 중 8 이하는 **0쌍**이다. 선대로면 "예산이 뚫을 여지가 있다".

⚠️ **그런데 축 개수는 예산 단위가 아니다.** 예산은 `숫자 리터럴 +
가중치 개수` 를 센다. 실제 규칙은 한 항에 축을 여럿 담는다:

```python
s = s + np.where(p.is_memory_bound, f.log_dram_traffic, f.log_inst_total) * w[4]
#          술어 1 + 피처 2 = 축 3개를 가중치 1개로
```

측정하면 한 항이 축(술어 포함)을 **1.62~2.50개(중앙 2.12)** 담는다.
9개 규칙 전부 8항이면서 축은 13~20개를 쓰고 있다.

```
계열 사이 합집합 (축+술어)   18~22
그 밀도로 담으려면           ★ 9.4항
-> 8 은 모자란다. 부족분 약 1.4항. 16 은 넉넉하다.
```

**"8 이하" 라는 선은 1항=1축을 가정한 것이고 데이터가 그것을 부정한다.**
선의 방향(예산이 뚫을 여지가 있다)은 옮긴 단위에서도 같지만, **여유가
1.4항뿐**이라는 것이 원래 선에서는 안 보였다.

## 4. 상한 측정의 다섯 축은 regret 규칙에도 있다

```
                       regret     순위
split_k_cost            6/6        3/3
sm_idle_cost            5/6        3/3
waves                   4/6        3/3
pipeline_warmup_frac    4/6        2/3
tail_waste              2/6        2/3
```

**상위 100 안에서 크게 변하는 다섯이 `regret` 규칙에 이미 들어 있다.**
순위 능력의 차이는 "그 축을 안 봤다" 로는 설명되지 않는다.

---

## 5. 그래서 예산 16 에 대한 예상

두 갈래가 서로 다른 쪽을 가리킨다.

```
축 용량      합집합이 8항에 1.4항 모자란다        -> 16 이 도울 수 있다
기전        두 계열이 **같은 축**을 쓰고 (자카드 1.000)
            차이가 가중치에 있다 (D-103)          -> 16 이 안 도운다
```

★ **예상: 예산 16 은 벽을 못 뚫는다.** regret 재적합 tau 가 8 에서
−0.059~0.058 이었는데 16 에서도 그 띠 안에 남을 것으로 본다. 근거는
자카드 1.000 이다 — 담을 축이 모자란 것이 아니라 **같은 축을 놓고
가중치 하나가 두 순서를 동시에 못 만든다.**

다만 16항은 **같은 축을 서로 다른 술어와 가중치로 여러 번** 쓸 수 있게
한다. 그 자유도가 벽을 뚫는다면 예상이 틀린 것이고, 그때는 벽이
"표현력" 문제였다는 뜻이 된다. 그것을 재려고 돌린다.
