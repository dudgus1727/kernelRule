## 무엇을 묻는가

**"프롬프트를 기준선 문구로 되돌리면 요구 빈도가 돌아오는가."**

2차(D-80)에서 빈도가 0~5.9% 로 눌렸다 (기준선 12.5~23.5%). 억제 문구는
이미 뺐는데도 그랬고, 남은 원인은 프롬프트 개편의 다른 부분이었다.

## 되돌린 것 — **복원이지 튜닝이 아니다**

기준선이 측정된 문구로 **정확히** 돌아갔다. 새 문구를 만들어 넣은 것이
아니다. 논거는 실행 전에도 유효하다: 기준선이 그 문구로 측정됐으므로,
다른 문구로 재면 두 변수가 다르다.

```diff
- 목록에 없는 물리량이 필요하면 `physical_requirement` 에 **그 물리량이
- 무엇인지 한 문장으로** 쓰세요. 그것을 읽고 다른 사람이 피처 함수를 만듭니다.
- ✅ "split-K 가 만드는 CTA 병렬성 이득 …"   ⛔ "사례 #7 에서 …"
- **그 사람은 이 리포트를 못 봅니다.** … 전달되지 않고 버려집니다.
- 정말 기존 피처로 못 재는 것일 때만 채우세요. 있는 것으로 잴 수 있으면
- `measurable_with` 를 쓰는 편이 낫습니다.
+ 목록에 없는 물리량이 필요하면 `needs_new_feature` 에 그 이름을 쓰세요
+ (대부분의 라운드에서는 `null` 입니다 — 물리량이 그렇게 많지 않습니다).
```

**스키마 필드도 되돌렸다** — 그 설명도 모델에 간다.

```diff
- physical_requirement: "기존 피처로 못 재는 물리량이 있으면 그것이 무엇인지
-   한 문장으로. 이 문장만 피처 작성자에게 전달된다 — 사례 번호·점수·형상은
-   쓰지 마라(전달되지 않는다). 아니면 null"
+ needs_new_feature: "기존 피처로 못 재면 그 물리량의 이름. 아니면 null"
```

**억제 문구("대부분의 라운드에서는 `null`")도 기준선의 일부라 그대로
되살렸다.** 그것만 빼면 그것이야말로 새 조건이다.

`loop._requirement_of` 는 **두 이름을 다 읽는다** — 그 사이에 만든
실행 3개가 조용히 0건이 되면 안 된다.
`test_analyze_prompt_matches_the_measured_baseline` 이 문구를 고정한다.

## ★ 표본의 단위는 **실행**이다 (원칙 28)

한 실행의 가설들은 같은 씨앗·같은 계보에서 나온다. 제안/가설 단위로
세면 n 이 부풀고 한 실행의 습관이 모집단 비율로 읽힌다.

```
표본 하나 = 실행 하나의 요구 비율 (1차 Analyst, r0~r3)
기준선   6실행  12.5  22.2  20.0  23.5  16.7  21.1 %   (중앙 20.5%)
새 조건  6실행
검정     Mann-Whitney U (단측: 새 < 옛)
```

## ★ 검정력 — 실행 단위로 다시 계산했다

```
6 vs 6 의 최소 가능 p (완전 분리) = 0.00063

진짜 비율   '눌렸다' 로 유의 판정할 확률
   5%              99.6%
   9%              85.4%      <- 2차의 3실행에서는 20% 였다
  13%              43.7%
  17.9% (기준선)     7.7%      <- 오탐률
```

**9% 억제를 85% 확률로 잡는다.** 3실행에서 못 잡던 크기다.
**13% 는 여전히 절반쯤 놓친다** — 그 사실을 미리 적는다.

## 판정 — 미리 적는다

```
p >= 0.05         복원 성공으로 본다. ★ 단 "같다" 가 아니라 "구분 불가" 다
                  13% 급 억제는 44% 확률로만 잡힌다
p < 0.05, 새<옛   ★ 여전히 눌린다. 남은 차이(D-78 / 경로 자체)를 의심한다
                  프롬프트는 이미 기준선과 같으므로 프롬프트 탓이 아니다
p < 0.05, 새>옛   ★ 예상 밖. 복원이 과했는지 본다 (그럴 이유는 없다)
```
