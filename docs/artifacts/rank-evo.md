| 미리 박은 선 | 결과 |
|---|---|
| 상위100 tau >= 0.30 → **성공** | ✅ 중앙 **0.389**, 3시드 전부 0.30 이상 |

| 전구간 tau >= 0.30 유지 | ✅ 중앙 **0.396** |
| 전구간 tau <= 0.15 → trade-off | — |

**★ trade-off 가 아니었다.** 배관 단계에서 전구간 tau 가 -0.09 까지
내려가 "상위권을 얻고 굵은 순위를 잃는다" 로 보였는데, **12라운드
진화에서는 둘 다 올랐다.**

```
씨앗            상위100 0.109   전구간 0.376
regret 진화     상위100 0.141   전구간 0.30~0.56
★ 순위 진화     상위100 0.389   전구간 0.396
```

**상위권은 regret 진화의 2.8배**이고 전구간은 그 범위 안에 있다.

⚠️ **3시드는 유의성을 못 낸다.** 범위 분리로 읽는다 — 상위100 tau 의
범위(0.307~0.395)가 regret 진화의 중앙(0.141) 및 씨앗(0.109)과 겹치지
않는다.

## ★ 대조 사다리 — 각 단계가 하나씩만 다르다

```
                                  상위100 tau   전구간 tau    셀
1  프롬프트 regret + 절대 경계        0.215       -0.093       2
2  프롬프트 regret + ★ 4분위          0.276       +0.067       8
3  프롬프트 순위손실 + 4분위 (본 실행) ★ 0.389      ★ 0.396    10~16
```

```
1 -> 2   ★ 셀 축의 효과
2 -> 3   ★ 프롬프트의 효과 (+ 라운드 2 -> 12)
```

⚠️ 1·2 는 **1시드 2라운드**이고 3은 3시드 12라운드다. 라운드 수가
2→3 에 섞여 있어 프롬프트만의 효과로 못 읽는다. **사다리는 방향만
읽는다.**

⚠️ 1·2 가 우연히 생겼다 — `LLMConfig` 에 `objective` 를 안 넘겨서
프롬프트가 `regret` 이었다. `config.json` 의 `llm.objective` 로
확인했다. **재현하려면 그 값을 명시해야 한다.**

★ 그리고 1→2 는 **모델이 목표를 모르는 상태**에서 일어났다 —
채택 기준만 바꿔도 움직인다. D-89("가설이 방향을 준다")와 같은 계열로,
여기서는 **"채택이 방향을 준다"** 다.

## ★ 상한이 지목한 축이 실제로 쓰인다

`ranking-ceiling.md` §3 에서 상위 100 안에서 크게 변하던 다섯:

```
split_k_cost          CV 0.70   ->  3/3 실행이 쓴다
sm_idle_cost          CV 0.54   ->  3/3
pipeline_warmup_frac  CV 0.45   ->  2/3
tail_waste            CV 0.39   ->  2/3
waves                 CV 0.39   ->  3/3
```

**상한 측정이 "여기서 달라진다" 고 한 축을 진화가 실제로 골랐다.**
손실이 목표를 옮겼다는 직접 증거다.

⚠️ 세 실행의 축 합집합이 **19개 전부**다 — 즉 "다섯만 쓴다" 가 아니라
"다섯이 항상 들어 있다" 다. 배타적 선택의 증거는 아니다.
