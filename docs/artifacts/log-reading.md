## 2. 거부 — ★ 34건 중 34건이 **인프라 문제**

```
사유별 합계   run 34 · static 26 · sandbox 3
```

| 횟수 | 종류 | 사유 |
|---:|---|---|
| **34** | run | **`KeyError: '__import__'`** |
| 12 | static | AST 노드 401~465 > 400 |
| 1 | static | 등록되지 않은 형상 수준 값: `p.waves` |
| 1 | static | 허용되지 않은 numpy 함수: `np.exp2` |
| 3 | sandbox | 타입 오류 등 |

### ★ `KeyError: '__import__'` 는 **규칙 잘못이 아니다**

재현했다:

```python
code = "def score(f, p, hw, w):\n    s = np.log(f.waves - 5.0) * w[0]\n    return s"
fn = compile_rule(code); fn(F(), None, None, w)
-> ★ KeyError: '__import__'

np.seterr(all="ignore") 를 먼저 부르면
-> [nan nan nan]   (그리고 nan 은 우리가 명시적으로 처리한다)
```

**numpy 가 경고를 내려고 `warnings` 를 import 하는데, 제한된 builtins 에
`__import__` 가 없어서 죽는다.** 규칙이 `log(음수)` · 0 나누기 · overflow
를 한 번이라도 만들면 그 규칙은 **채점도 못 받고 버려진다.**

★ **샌드박스 자식에는 이미 이 방어가 있다** (`sandbox.py:137`,
`np.seterr(all="ignore")`, 주석까지 달려 있다). **채점·적합 경로에는
없다** — `loop.py` 의 `compile_rule` 자리 다섯 곳과 `canonical.py`.

```
버려진 제안   34개 / 1,728개 = 2.0%
그 규칙들이 나빴는지 좋았는지 ★ 우리는 모른다 (점수가 안 났다)
```

### AST 노드 상한은 **아슬아슬하게** 넘는다

12건 전부 401~465 다 (상한 400). 파라미터 8 의 `ast_nodes` 상한이고,
모델이 조금씩 넘긴다. **상한을 바꾸면 조건 변경이므로 여기서 안 고친다.**

### 거부가 뒤 라운드에 몰린다

```
r1~r7    1 2 4 4 3 1 2
r18~r23  4 4 5 8 3 9
```

규칙이 자라면서 노드 상한과 실행 오류가 함께 는다.

## 3. 죽은 항 — **8자리 중 죽은 것은 4/48 뿐이다**

```
실행           항  죽은 항  자리별 손해 (0 에 **묶었을 때** 학습 regret 증가)
F3rw-p8-s0     8     0   w0:+0.9370 w1:+0.1858 w2:+0.0303 w3:+0.0921
                         w4:+0.0249 w5:+0.2901 w6:+0.0371 w7:+0.0058
F3rw-p8-s1     8     1   w0:+0.0240 w1:+0.0088 ★w2:+0.0000 w3:+0.0333
                         w4:+0.1165 w5:+0.0829 w6:+0.1491 w7:+0.0411
F3rw-p8-s2     8     1   w0:+0.1067 ★w1:+0.0000 w2:+0.0381 w3:+0.0456
                         w4:+0.1193 w5:+0.0681 w6:+0.2386 w7:+0.0453
F3rw-p8-s3     8     1   w0:+0.2460 w1:+0.0000 w2:+0.0509 w3:+0.1033
                         w4:+0.0363 w5:+0.0029 ★w6:+0.0000 w7:+0.1195
F3rw-p8-s4     8     1   w0:+0.1587 w1:+0.0003 w2:+0.0284 w3:+0.0596
                         w4:+0.0379 w5:+0.0411 ★w6:+0.0000 w7:+0.0537
F3rw-p8-s5     8     0   w0:+0.2695 w1:+0.0228 w2:+0.0735 w3:+0.0202
                         w4:+0.0386 w5:+0.0866 w6:+0.0536 w7:+0.0166
```

**48자리 중 4자리(8%)만 죽었다.** 파라미터 8을 거의 다 쓰고 있다 —
"자리가 남는다" 는 얘기가 아니다.

★ **첫 자리가 지배한다**: `w0` 을 빼면 손해가 +0.024 ~ **+0.937** 이다.
여섯 실행 전부에서 `w0` 이 상위권 손해다.

⚠️ **판정이 아슬아슬한 자리가 있다.** `s3 w1` 과 `s4 w1` 은 손해가
4자리 아래(+0.0000 / +0.0003)인데 문턱 `1e-6` 을 넘어 "안 죽었다" 로
셌다. 문턱을 여기서 다시 정하지 않는다 (원칙 7) — **"죽은 자리 0~2개,
48자리 중 4~6개"** 로 읽는 것이 정직하다.

### ⚠️ 정정 이력 — 처음 낸 표는 **항을 안 뺐다** (D-136)

처음 절차는 `w[i]=0` 을 **시작점**으로 주고 다시 맞췄다. 적합기가 그
자리에서 되돌아 나오므로, 재던 것은 "죽은 항" 이 아니라 **"시작점을
흔들어도 같은 점을 찾나"** 였다. 확인:

```
F3rw-p8-s3, i=0   w[0] 3.18 -> 0 에서 출발 -> ★ 끝 0.60 (되돌아 나왔다)
                  묶지 않음 regret 1.08382 = 기준  -> "죽었다" 로 셌다
                  ★ 0 에 묶으면    1.32985       -> 전혀 안 죽었다
```

**처음 낸 (틀린) 표 — 지우지 않고 남긴다:**

```
F3rw-p8-s0  8  0
F3rw-p8-s1  8  1   w[2]<-r0
F3rw-p8-s2  8  3   w[0]<-r0, w[2]<-r0, w[4]<-r0
F3rw-p8-s3  8  7   w[0] w[1] w[3] w[4] w[5] w[6] w[7] <-r0
F3rw-p8-s4  8  3   w[1]<-r0, w[4]<-r0, w[6]<-r0
F3rw-p8-s5  8  2   w[1]<-r0, w[6]<-r0
합계 16/48 (33%)   ->  ★ 고친 절차로는 4/48 (8%)
```

`bounds` 로 그 자리를 `(0,0)` 에 묶어 고쳤다 — `_proj` 가 **모든 목적함수
평가에서** 클립하므로 Nelder-Mead 에서도 유효하다.

그리고 "그 항이 언제 들어왔나" 열을 **뺐다**: 씨앗 규칙이 이미 8자리를
다 쓰므로 첫 등장이 전부 `r0` 이고 아무것도 말해주지 않았다.
