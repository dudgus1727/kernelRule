# ★ Analyst 는 비용이 아니라 **절약**이다 (2026-08-29)

**헤드라인은 성능이 아니다.** Analyst 를 끄면 호출이 7.7% 줄지만
**채점된 후보당 비용이 2배가 된다** — 방향이 없으면 Optimizer 가 같은
규칙을 반복하고, 중복은 채점조차 안 된다.

```
채점된 제안 / 전체    Analyst 있음 84% 90% 92%    없음 28% 53% 47%
채점 후보당 호출       1.2회                       ★ 2.4회
```

성능 차이(시드 폭의 3.7배, 범위 분리)는 그 결과다.

> **실험 계획서** [ablation-prereg.md](ablation-prereg.md) (LLM 호출 0회 상태)
> **재현**
> ```
> python3 experiments/f1_pipeline.py F3 --stage 3 --tag abl-B \
>     --seed-from runs/f1pipe-F3-arch24 --rounds 12 --n-seeds 3
> python3 experiments/f1_pipeline.py F3 --stage 3 --tag abl-A --no-analyst \
>     --seed-from runs/f1pipe-F3-arch24 --rounds 12 --n-seeds 3
> ```
> **모델** `gpt-5.6-luna` medium · **표** dev-cu124 · **씨앗 고정** (D-88)
> **비용** 900호출 (실험 계획서 예상과 같다)
> **성능 수치를 인용하지 않는다** — 조건 간 차이만 쓴다

## 1. ★ 주 지표 — 범위가 완전히 안 겹친다

구조 홀드아웃 regret (`n_val=20`, 낮을수록 좋음). 표본 하나 = 실행 하나.

| | 실행별 | 중앙 |
|---|---|---:|
| **B (Analyst 있음)** | 1.0704  1.0779  1.0680 | 1.0704 |
| **A (없음)** | 1.1177  1.1161  1.1163 | 1.1163 |

```
차이 +0.0459   ★ 시드 폭 σ=0.0124 의 3.7배
범위 겹침 없음
Mann-Whitney 양측 p = 0.100
```

⚠️ **`p = 0.100` 은 "유의하지 않다" 가 아니다.** 3 대 3 에서 **완전
분리일 때 나오는 최솟값**이다 (실험 계획서에 미리 적었다). 이 표본으로
낼 수 있는 최대 증거이고, 그래서 판정은 **범위 분리와 시드 폭**으로
한다 — 둘 다 통과했다.

## 2. ★ 기전 — Analyst 가 없으면 Optimizer 가 **같은 규칙을 반복한다**

이것이 이번 실험에서 가장 값진 관찰이다. 성능 숫자보다 먼저 온다.

| | 채점된 제안 / 전체 |
|---|---|
| B | 121/144 (84%) · 129/144 (90%) · 133/144 (92%) |
| **A** | **40/144 (28%)** · 76/144 (53%) · 67/144 (47%) |

제안 수는 양쪽 다 144 로 같다. **차이는 전부 중복이다** — 이미 본 코드는
`_seen_code` 캐시가 걸러 채점조차 안 된다.

```
가설이 없으면 Optimizer 는 "점수를 낮춰라" 만 듣는다.
방향이 없으니 같은 자리를 다시 판다.
```

### 비용을 다시 읽어야 한다

```
호출 수      A 144 / 실행,  B 156 / 실행     -> A 가 7.7% 싸다
★ 채점된 후보당 호출  A 2.4회,  B 1.2회      -> ★ A 가 2배 비싸다
```

**"Analyst 는 호출의 8% 를 쓴다" 는 계산이 틀렸다.** 그 8% 를 아끼면
나머지 92% 의 절반 이상이 중복으로 버려진다.

## 3. 언제 멈추는가 — A 는 r2~r4 에서 멈춘다

검증 regret 이 마지막으로 개선된 라운드:

```
B   r9   r7   r8
A   r2   r3   r4     ★ 이후 8~9라운드가 통째로 헛돈다
```

**12라운드가 A 에게는 낭비다.** 그리고 이것은 "A 가 나쁘다" 보다 정확한
서술이다 — A 는 **일찍 갇힌다.**

## 4. 규칙이 쓰는 피처 수 — D-83 의 축과 이어진다

```
아카이브 평균   B 15.3 · 13.2 · 13.3     A 12.0 · 11.8 · 10.9
최선 규칙       B 18 · 13 · 17           A 11 · 13 · 11
```

**Analyst 가 있으면 규칙이 더 많은 물리량을 쓴다.** D-83 에서 "규칙이
쓰는 피처 수" 와 "새 축 요구율" 이 rho=+0.566 으로 붙어 있었는데,
여기서 그 축의 **상류**가 보인다 — 가설이 항 선택을 이끈다.

⚠️ 범위가 살짝 겹친다 (B 최소 13.2 vs A 최대 12.0 은 안 겹치지만,
최선 규칙은 B 13 vs A 13 이 겹친다). **성능만큼 깨끗하지 않다.**

## 5. 겹치는 것 — 다양성 지표는 구분 못 한다

```
아카이브 셀 수   B 11 · 5 · 7      A 4 · 6 · 9      ★ 겹친다
정적 거부 수     B 10 · 6 · 9      A 0 · 1 · 0
```

**셀 수로는 못 가른다.** 그리고 A 가 정적 검사에 거의 안 걸린다 —
반복적인 제안이라 새로운 위반을 안 만든다. **"거부가 적다" 가 좋은
신호가 아닌 경우다.**

## 6. 판정 — 실험 계획서의 첫 갈래

```
"B 가 낫고 범위가 안 겹친다 -> ★ 진단 리포트가 기여한다. §16.1 의 직접 증거"
```

**§16.1 이 처음으로 측정됐다.**
