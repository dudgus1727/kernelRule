# 용어집

**이 문서가 이름의 유일한 출처다.** 이름이 잘못된 대비를 만들면 그 위에
결론이 쌓인다 — 실제로 그랬다 (`artifacts/conclusion.md` 의 정정 이력).

---

## ★ 쉬운 말 대응표 (2026-09-04, D-132)

한자어 번역이 쌓여 읽기 어려웠다. **이름만 바꿨고 가리키는 절차는
그대로다.** 옛 커밋 메시지와 산출물 json 에는 옛 말이 남아 있다 —
이 표가 그것을 잇는다.

| 옛 말 | 지금 말 | 가리키는 것 (안 바뀐다) |
|---|---|---|
| 정본 | **대표값** | 그 조건의 기준이 되는 실행 묶음과 그 점수 |
| 정준 / 정준 채점 | **최종 채점** | 학습 분할 전체에 가중치 ★ 한 벌을 맞추고 홀드아웃 전체에서 재는 절차 (`core.canonical.canonical_score`). ⛔ D-179 이전에는 둘로 갈라 두 벌을 맞췄다 |
| 정준값 | **최종 점수** | 위 절차의 결과, 6실행 중앙값 |
| 사전 등록 | **실험 계획서** | 계산·호출 **전에** 판정선과 해석을 적어 두는 문서 |
| 관문 | **통과 조건** | 다음 단계로 갈 수 있는지 가르는 검사 |
| 잔여 | **남은 것** | — |
| 갈린다 | **달라진다 / 어긋난다** | 두 값·두 조건이 같지 않다 |
| 통화 (D-131) | (비유였다) | "어느 점수로 재느냐" |

★ 함수 이름 `canonical_score` 는 그대로다 — 코드 식별자는 안 바꿨다.

## 규칙의 출처

두 규칙 **모두 LLM 이 썼다.** 사람은 방향을 정하고 물리 오류를 지적했지
규칙 코드를 쓰지 않았다.

| 이름 | 무엇 | 무엇에 맞췄나 |
|---|---|---|
| **`human_guided`** (개명 전 `physics_seeded`, D-128) | Claude Code 가 물리 문서를 읽고 **한 번에** 작성 (`rules/human_guided.py`). ★ 그 뒤 표 관측으로 **네 판** 고쳤다 (1.776 -> 1.192) | 물리 + 표 요약 |
| **`evolved`** | 그 파이프라인이 GPT 로 20라운드 진화 (`runs/*/archive.jsonl`) | 학습 분할 regret |

> ⛔ **`handwritten` / `손규칙` 은 쓰지 않는다.** "사람 대 LLM" 이라는 틀린
> 대비를 만든다. 차이는 **누가** 가 아니라 **무엇에 맞췄는가** 다.

두 규칙의 입력 차이가 결과 차이를 만들었다 — ★ 어느 쪽도 "표를 안 봤다" 가 아니다:

| | `human_guided` | `evolved` |
|---|---|---|
| 입력 | 물리 문서 + 요약 통계 | 사례 15개 + regret |
| 요구 | "물리를 코드로 옮겨라" | "이 가설을 반영해라" |
| 피드백 | 물리 오류 지적 3회 | 점수 |
| 목적함수 | 없음 (구조만) | 학습 분할 regret |

## 체제 (regime)

**성능을 지배하는 물리가 다른 형상 그룹.**

⛔ **2026-09-17 (D-179) — 주 축이던 것을 지웠다.**

여기에는 커널 실행 시간을 **우리가 고른 문턱**으로 갈라 "빠른 체제 / 느린
체제" 로 부르는 절이 있었다. 정의·형상 수·대리 지표의 공식·일치율 실측이
함께 있었다. 그 축은 코드에서 없어졌고 다시 만들 수 없다.

```

            ★ 그 문턱으로 채점이 가중치를 두 벌 맞췄다 — 벤더에는 없는 자유도
            ★ 루프는 한 벌로 진화했다 — 최적화한 목적과 보고값이 다른 함수였다
어디에 남나  ★ D-179 항목 하나에만. 이 낱말로 낸 옛 수치는 기록에 그대로 있다
```

## 노이즈 바닥 (noise floor)

```
noise_floor(t) = max(sigma_rel(t), tick_pct(t))
```

형상마다 다르다. 통계적 흔들림은 평균으로 줄지만 **눈금 해상도는 줄지
않는다.** 이 값보다 작은 차이는 순위가 아니다 (§30).

## regret

```
regret@k = (규칙이 고른 상위 k 중 최선의 시간) / (그 형상의 최적 시간)
```

집계는 기하평균. **전체 geomean 하나만 보고하지 않는다** — 소수 형상의
큰 손실에 끌린다 (§30.4). 승패 카운트를 함께 낸다 (`core/scoring.compare`).

## 통과 조건 (gate)

**벤더 휴리스틱 nearest, 전체 61형상 `1.0797`.** 이것을 유의하게 이기지
못하면 규칙을 배포할 이유가 없다 (§9.2).
